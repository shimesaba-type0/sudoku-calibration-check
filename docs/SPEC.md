# 仕様書 — 数独キャリブレーションチェック

最終更新: 2026-09-21 / 対象バージョン: v0.1

## 1. 目的と背景

TypeSafe AI の **Jev** は「文章を生成せず、型付きの判断を較正された確率つきで返す」モデルとして2026-09-15に公開された。公開ベンチマークが意図的に出されておらず、「確率が本当に較正されているか」を第三者が検証する手段がほぼない。

数独は **唯一の正解が機械的に確定できる** 珍しい題材である。「このマスは5である確率は?」という問いに対して、Jevが返した確率と実際の正解を突き合わせれば、Jevの主張を自分の目で確かめられる。本アプリはそのための実験装置であり、同時に「Jevに向いていないとされる System 2 タスク(多段階の論理推論)を、文脈を増やした反復でどこまで補えるか」を観察する装置でもある。

ゴールは「数独をJevで解くこと」ではない。**Jevの確率の信頼性を可視化すること**。

## 2. 用語

| 用語 | 意味 |
|---|---|
| Jev | TypeSafe AI の System One モデル。Cloudflare Workers AI では `typesafe/jev` |
| Choice | Jev のプリミティブの1つ。定義した選択肢から1つ選び、全選択肢の確率を返す |
| Noul | 真偽を 0〜1 の確率で返すプリミティブ(本アプリでは未使用、将来の転用先) |
| state | Jev に渡す判断対象。文字列・オブジェクト・配列のいずれか |
| 周(round) | 未確定マス全部を1回ずつ判定する1サイクル |
| スナップショット | 「与えられた数字 + それまでの周で埋まった推測(正誤問わず)」を9行の文字列で表した盤面 |

## 3. 機能要件

### F1. 画面構成

- **難易度切り替え**: 「やさしい」「ふつう」「むずかしい」の3択トグル(既定「ふつう」)。ヒント数(与えられた数字の数)を切り替える。変えただけでは盤面は変わらず、次の「新しい問題」から効く

- **順番切り替え**(Issue #38・#48): 「左上から」「確信度順」「一括」の3択トグル(既定「左上から」)。モデル切り替えと同じ条件で実行中・停止中はロックする(周の途中で選び方が混ざると周回ログの意味が崩れるため)。選択は `localStorage` には保存せず、実行中の `state` としてのみ `reset()` / 「新しい問題」をまたいで保持する(F3)
- **消去法の2トグル**(Issue #61・#63、F3): 「消去法(履歴): あり / なし」(既定あり)と「ルール候補: あり / なし」(既定あり)。順番トグルと同じ条件でロックし、`localStorage` には保存せず `reset()` / 「新しい問題」をまたいで `state` として保持する。URL パラメータ `history=0|1` / `rules=0|1`(不正値は無視、F1')で初期値を上書きできる。比較シェル(`/compare`)の上部バーにも同じ2トグルがあり、両 iframe に `postMessage` する
- **Claude の設定パネル**(モデルが「Claude」のときだけ表示。7章 拡張3、Issue #37): API キーの入力欄(`type=password`)と「保存」「キーを消す」ボタン、保存状態(未設定 / 保存済み(末尾 4 文字))、モデル選択(`claude-opus-5`(既定)/ `claude-sonnet-5` / `claude-haiku-4-5`)、思考(extended thinking)の「思考あり」「思考なし」トグル。キーは **このブラウザの `localStorage`(`scc.anthropic_key.v1`)にだけ保存し、`api.anthropic.com` への呼び出し以外には送らない**(Worker には渡らない)。キーの値そのものは画面に出さない
- **単価パネル**(Issue #56、5章): モデルごと(`typesafe/jev` / `claude-opus-5` / `claude-sonnet-5` / `claude-haiku-4-5`)の入力/出力単価(100万トークンあたり USD)の入力欄と「既定値に戻す」ボタン。Claude モードに限らず常時表示する(Jev の単価も編集できるように)。値は `localStorage`(`scc.prices.v1`)に保存し、不正値(数値でない・負)は既定値にフォールバックする。単価は表示時の計算にだけ使う(記録そのものには単価を焼き込まない)
- **この実行の消費パネル**(Issue #55・#56、オーナー追加要望 2026-09-23): 単価パネルは「単価の定義」であって、いま実際にどれだけ消費したかが一目でわからないという指摘への対応。単価パネルのすぐ上に置き、`reset()` されるまでの累計を表示する: トークン(入力/出力の合計)・コスト(`formatUsdForModel(totalCostUsd, ...)`)・速度(平均 `tok/s`。API 呼び出しの待ち時間の合計 ÷ 累計トークン数の逆数、トークンが無い・経過200ms未満のときは「—」。**「最速」モードのときだけ表示**。オーナー追加要望 2026-09-23)。`render()` のたびに更新する(現在の判定パネルの経過行と同じ更新頻度)。単価パネルの見出しも「単価の設定(…実際の消費は上の「この実行の消費」欄)」に変えて誤解を防ぐ
- **実行 / リセット / 新しい問題** ボタン
  - 「実行」ボタン(`id="run-btn"`)は実行中だけ**「停止」に切り替わる**(押すと止まる)。停止中(実行を始めた後、止めていて、完了もエラーもしていない状態)は**「再開」**になり、押すと続きから動く(F2/F3)。「リセット」「新しい問題」は停止中も押せる
  - 「リセット」は **現在の問題をやり直す**(盤面・周回ログ・統計を捨てて1周目の最初から)
  - 「新しい問題」はジェネレーターで別の問題を作って差し替える(ソルバーで一意解を確認済み)。生成中はボタンが「生成中…」になり、実行中と生成中は押せない。初期表示は Wikipedia の固定問題
- **数独グリッド**(9×9、3×3の区切り線を太くする)
  - 与えられた数字: 白・太字
  - 未判定: 空白
  - 判定中(フォーカス): アクセント色の枠線(inset)
  - 正解: 緑の数字と薄い緑背景
  - 不正解: 赤の数字と薄い赤背景
  - **確信度順モードのヒートマップ**(Issue #38): マス選びの直後、選ばれなかった候補マス(未判定・非フォーカス)の背景をアクセント色の薄い塗り(`rgba(125, 211, 252, α)`、`α = 0.08 + 0.6 * p / pmax`。`p` はそのマスがマス選びで選ばれる確率、`pmax` は候補内の最大値)で示す。選ばれたマス(フォーカス)は従来どおり枠線。数字が確定したら消える(次のマス選びまで出ない)。**2周目以降の候補マスは前の周の不正解の数字(赤背景)を持つので、ヒートマップは事実上1周目だけ出る**(赤/緑の意味を優先し、上に重ねない。パネルの「マス選び: N 候補中 …(p%)」で選ばれたマスの確率は周によらず読める)
- **統計カード**(5つ、Issue #60): 現在の周 / 残りマス / 累計正解 / この周の判定済み / この周の正解。以前は「この周の進捗(判定済み数/対象数)」の1枚だったが、正解率に見えてしまう(不正解が残っていても「7 / 7 (100%)」のように出る)ため、判定済み数(`roundTally.total / roundSize`)と正解数(`roundTally.correct / roundSize`、正解率つき)の2枚に分けた
- **現在の判定パネル**: 冒頭に **実行中の経過(ミリ秒)と累計コスト**(「経過 3,214 ms / $0.0004」。Issue #55・#56)。`render()` のたびに更新するだけで、走っていないとき(停止中・完了後)は最後の値のまま残る。続けて、判定中マスの座標(「3行目 6列目」形式)と、1〜9の横棒グラフ(確率%)。`choice` の棒だけアクセント色(`choice` は必ずしも argmax ではない。`docs/DESIGN.md` 3.4)。結果を待っている間・確定直後は、直前に確定した判定(座標・選んだ数字・正誤・確率バー)を次の結果が来るまで残す(最速モードでも見えるように)。**停止中は「停止中(残り N マス)」を表示し、フォーカスの枠線は消える**(F2)。**一時的な失敗による停止(Issue #43、F5)** では、その下に赤系の理由の箱(`class="pause-reason"`)を添える。手動で「停止」したとき(理由なし)は出ない。**確信度順モード**(Issue #38): マス選び中は「マス選び中…(候補 N マス)」、マス選びが終わってから数字が確定するまでは、座標・バーの先頭に「マス選び: N 候補中 r行目c列目(p%)/ confidence q%」を添える。**一括モード**(Issue #48): 応答が届くまでは「一括で判定中…(N マス)」、届いたあとは各マスとも既存どおり座標とバーを表示する
- **モデルに送ったプロンプト**: 直近の判定で Worker が Jev に渡したペイロード(`request`)、または Claude 経路ならブラウザが `api.anthropic.com` に送ったリクエストボディ(ヘッダーは含めない = キーは出ない)を JSON で表示し、対象マス(「N行目 M列目 の判定に使用」)を添える。判定が 502 で失敗したときはその `request` を「(このプロンプトで失敗)」付きで表示する。まだ無ければその旨。停止中・エラー中も残り、リセット/新しい問題で消える。**確信度順モード**(Issue #38): 「マス選び」見出し + マス選びに使ったリクエスト、続けて「数字」見出し + 従来どおりの数字判定のリクエストを2段で表示する。**一括モード**(Issue #48): 「一括」1段で、質問が空マスの数だけあり大きいので「質問 N 問」の要約行 + 折りたたみ(`<details>`)で表示する。失敗時は「(このプロンプトで失敗)」を既存どおり添える
- **凡例**: 正解・不正解・判定中の色の意味。確信度順モードのときだけ「背景の濃さ = マス選びの確率」を1項目足す
- **周回ログ**: 「N周目: M中K正解 (P%) — 3,214 ms / $0.0004」を周ごとに追記(Issue #55・#56。`ms` はその周で最初のリクエストを送った時刻から周が終わるまでの走っている時間(停止中は含まない)、`$` はその周のコスト)。**強制終了(15周の安全弁)したときは、通常の行の直後に「15周で強制終了(最終周の不正解 N マス)」を専用の1行足す**(Issue #60。`N` はその周の不正解数。既存の合計行より前に置く)。完了/強制終了したときは末尾に合計行「合計 12,345 ms / $0.0012(3周)」を1行足す(`ms` は「実行」から完了までの走っている時間、`$` は累計コスト、`3周` は強制終了の行を除いた実際の周数)。単価が見つからないモデル(5章)の行には「(単価未設定)」を添える
- **集計パネル(較正図)**: 周回ログの下に、これまでの判定結果(複数問題・複数回の実行をまたいでブラウザの `localStorage` に蓄積したもの)を集計して表示する(7章 拡張2)。モデルフィルタには記録の `m` の値がそのまま並ぶ(例: `typesafe/jev`、`typesafe/jev/all`(一括モード、F3)、`claude-opus-5+think`)
  - 上部に合計件数・全体正解率・記録している問題数(ユニークな問題ID)
  - `pc`(`choice` の確率)と `conf`(モデルの `confidence`)それぞれで10%刻み10帯に分けた較正図(インラインSVGの棒グラフ、横並び。理想は対角線)を並べる。帯ごとに件数と実際の正解率を示す
  - **モデルのフィルタ**(`<select>`): 「すべて」か、記録に現れるモデル識別子(`typesafe/jev` / `claude-opus-5+think` など。記録の `m`。`m` の無い古い記録は `typesafe/jev` 扱い)を選び、そのモデルの記録だけを集計する(Jev と Claude の較正を並べて比べるため。Issue #37)
  - 「JSONエクスポート」ボタン: 蓄積した記録一式を `sudoku-calibration-YYYYMMDD-HHMMSS.json` としてダウンロードする
  - 「記録を消す」ボタン: 確認ダイアログのあと、蓄積した記録をすべて削除する
- **完了バナー**: 全マス正解時に「N周ですべて正解しました」。**ページの一番上(見出しの直下、埋め込みモードでは最上部)に出す**(側面パネルの末尾だと見逃されるため。オーナー要望 2026-09-22)
- **強制終了バナー**: 15周の安全弁(F3)で止まったときに「15周で強制終了しました(最終周の不正解 N マス、全マス正解には至らず)」。位置は完了バナーと同じ。周回ログの各行に残る不正解数と合わせて、どこまで収束したかが読める
- **エラー表示**: API失敗時に赤いボックスでメッセージ表示。実行は停止する
- **比較モードへのリンク**(Issue #46): 見出し付近に「比較モード」への小さなリンクを置く。`/compare` に遷移する(下記)

### F1'. 比較モード(`/compare`)と URL パラメータ(Issue #46)

同じ問題を Jev と Claude に同時に解かせて見比べるための、通常ページとは別の画面。判定ループの `state` / `queue` / 実行世代はページに1組しかない設計を崩さないため、**Jev/Claude 2 インスタンス化はしない**。代わりに、通常ページ(`GET /`)を `<iframe>` で2枚並べ、`/compare` を返す親ページが `postMessage` で両方を同時に操作する(`docs/DESIGN.md` 4.2・8章)。

**通常ページ(`GET /`)の URL パラメータ。** `location.search` を起動時に1回読む(`readUrlOptions()`)。`localStorage` の設定より優先するが、`localStorage` へは一切書き戻さない(通常ページの設定を汚さない)。

| パラメータ | 意味 |
|---|---|
| `puzzle=<81文字>` | `1`〜`9` と `.` からなる81文字。この盤面で開く。`SOLUTION` はソルバー(`solveCount`)で求め、**一意解のときだけ**採用する(形式不正・非一意なら無視して固定問題のまま) |
| `model=jev\|claude` | モデル切り替えの初期値を上書きする |
| `order=scan\|confidence\|all` | 順番切り替えの初期値を上書きする |
| `speed=slow\|fast` | 速度切り替えの初期値を上書きする |
| `history=0\|1` | 消去法(履歴)トグルの初期値を上書きする(Issue #61)。`0`/`1` 以外は無視 |
| `rules=0\|1` | ルール候補トグルの初期値を上書きする(Issue #63)。`0`/`1` 以外は無視 |
| `embed=1` | 埋め込みモード(下記)にする |

**埋め込みモード(`embed=1`)。** コントロール群(実行/リセット/新しい問題/各トグル)・Claude 設定パネル・単価パネル・較正図・プロンプト枠・見出し(h1・サブタイトル)を隠し、グリッド・凡例・この実行の消費パネル・統計カード・現在の判定・周回ログ・エラーボックス・完了バナーだけを描く。親(比較シェル)からの `message` を、`event.origin` が自分と同一オリジンのときだけ受け付ける:

| `message` の `type` | 効果 |
|---|---|
| `run` | `run()` を呼ぶ |
| `stop` | `stop()` を呼ぶ |
| `reset` | `reset()` を呼ぶ |
| `newPuzzle`(+ `puzzle`) | `puzzle`(81文字)を上記と同じ検証で差し替える |
| `setSpeed`(+ `mode`) | 速度切り替え |
| `setOrderMode`(+ `mode`) | 順番切り替え |
| `setHistoryMode`(+ `on`) | 消去法(履歴)トグル(Issue #61) |
| `setRuleMode`(+ `on`) | ルール候補トグル(Issue #63) |

また、`render()` のたびに現況(モデル識別子・周・累計正解数・総マス数・残りマス・実行中か・停止中か・停止中の理由(一時的な失敗のときだけ。Issue #43)・完了か・完了周数・強制終了か・エラー文言・**`elapsedMs`(全体の走っている時間、ミリ秒)・`costUsd`(累計コスト、USD。Issue #55・#56)**)を `{ type: "status", ... }` として `window.parent` へ `postMessage`(第2引数に `location.origin`)する(`embed=1` のときだけ)。

**比較シェル(`GET /compare`)。** 上部バー(新しい問題 / 実行(どちらか一方でも実行中なら「停止」に切り替わり、両方に停止を送る。両 iframe から最初の `status` が届くまでは「読み込み中…」で押せない)/ リセット / 速度トグル / 順番トグル / 消去法の2トグル(履歴・ルール候補。Issue #61・#63、いずれも実行中・停止中のときはロック)/ 難易度トグル)と、左右2枚の `<iframe>`(`src="/?embed=1&model=jev&puzzle=…&speed=…&order=…&history=…&rules=…"` / `…&model=claude…`。初期盤面は固定問題)を並べる。各 iframe の上に、モデル名・経過時間(`elapsedMs` をミリ秒表記にしたもの。**子(iframe)が申告する値をそのまま使い、親側では計測し直さない**(Issue #55。以前は親が「実行」を押した時刻から秒単位で計っていたが、再開のたびにリセットされてしまう問題があった))・「N周目」・「正解 K / 総マス」・状態(実行中 / 停止中 / 停止中(一時的な失敗)(Issue #43) / 完了(N周) / 強制終了(15周) / エラー: 文言)・コスト(`costUsd` を `$` 表記にしたもの)の見出しを表示し、iframe からの `status` メッセージで更新する。Claude の API キーが未設定(`loadAnthropicKey() === null`)なら右側の見出しに注記を出す(キー入力はここには置かない。通常ページの設定パネルで保存する)。**片方がエラーで止まっても他方は続く。**

### F2. 1マスの判定フロー

**確信度順モード(Issue #38)では、この判定フローの前に「マス選び」が入る(F3)。** 以下は
選ばれたマス(左上からモードでは queue の先頭)に対する数字判定の手順で、どちらのモードでも共通。

1. 対象マスをフォーカス表示し、確率バーを空にする
2. モデルが「Jev」なら `POST /api/judge` にスナップショットと対象座標を送る。「Claude」なら **ブラウザから `https://api.anthropic.com/v1/messages` を直接呼ぶ**(BYOK。4章「Claude 経路」)。どちらも同じスナップショット(対象マスは `.`)を渡し、返ってくる形も同じ `{ probabilities, choice, confidence, request }` に揃える
3. 返ってきた `probabilities` を1〜9の順に並べてバー表示。`choice` の棒を強調
4. `choice` の数字をマスに入れる
5. 正解(`SOLUTION`)と比較し、緑/赤で色付け
6. じっくりモードなら 700ms 待ってから確定、確定後 150ms 待って次へ。最速モードは待ち時間ほぼゼロ

**停止(Issue #32)。** 「停止」を押すと、盤面(判定済みのマス)・周回ログ・統計・実行中の周は保ったまま止まる(リセットとは違い、進行状況を捨てない)。判定中(フォーカス中)のマスがまだ確定していなければ、その結果は破棄して記録にも残さない。**そのマスは「再開」(=実行の続き)でもう一度最初から聞き直す**(F1不変条件と同じく、確定していない推測を Jev に見せたまま次に進めることはしない)。判定中でない(結果待ち・確定直後の待ち時間中だけの)タイミングで止めた場合は、次のマスから続く。

### F3. 周回ロジック

- 1周目の対象は「与えられていないマス」すべて(行優先順)
- 周が終わったら「N周目: M中K正解 (P%)」をログに追記
- **不正解だったマスだけ**を次の周の対象にする。正解したマスは確定し、二度と判定しない
- 次の周の判定では、**前の周までの推測(正誤問わず)を含むスナップショット**を Jev に渡す。つまり周を重ねるほど文脈が増える
- ただし **再判定するマス自身は空(`.`)にして送る**。そのマスの前回の推測を Jev に見せない(アンカリングを避ける)
- 不正解が0になった周で終了。その周の番号を「何周で全部正解したか」として表示
- 安全弁として15周で強制終了
- **周をまたぐ待ち時間中(1周終わって次の周が始まるまでの間)に「停止」した場合は、次の周の先頭から再開する**(Issue #32)。次の周の対象マス・周番号は、この待ち時間に入る前(周が終わった直後)にすでに確定しているため
- **確信度順モード**(Issue #38、順番トグルで選ぶ)では、周の対象マスを左上から順に聞くのではなく、まず「その周でまだ確定していないマス(= その時点の `queue`)のうち、最も確定しやすいマス」を Worker の `ask:"cell"`(4章)/ Claude の同種のスキーマ(4章「Claude 経路」)で選ばせ(**マス選び**)、選ばれたマスを従来どおり `ask:"digit"` で聞く(F2)。**候補は常にその周の残りマス(`queue`)そのもの**で、マス選びに送る盤面は `queue` の全マスを `.` にしたスナップショット(`buildSelectionSnapshot()`。2周目以降は前の周の不正解の推測が残ったままだと Worker が空マスとして数えないため、これらも `.` にする必要がある)。選ばれたマスは `queue` から取り除いてから数字判定(F2)に進むので、1マスあたりの API 呼び出しが2回になる(5章)。周の区切り・集計・15周の安全弁は左上から順のときと同じ
  - マス選び中に「停止」した場合(まだどのマスも選ばれていない)は、選び直しから再開する(`queue` はそのまま。再キューは不要)。選ばれたあとの数字判定中の停止は F2 の従来どおり(`queue` の先頭に戻す)
- **数字ごとモード**(Issue #45)では、マスではなく数字を主語にして「この数字はどの空マスに入るか」を Worker の `ask:"where"`(4章)で一度に聞く。空マスごとの `noul` がまとめて返るので、**1 盤面 × 1 数字につき API 呼び出しは 1 回**(1〜9 を一通り聞くと 1 周あたり最大 9 回。左上からの 51 回、確信度順の約 102 回と比べる数字)。送る盤面はマス選びと同様、**その周でまだ確定していないマスを `.` にしたスナップショット**(`buildSelectionSnapshot()` 相当)にする(前の周の不正解の推測が残ったままだと Worker が空マスとして数えず、質問から漏れる)。**現時点では Worker 側(`ask:"where"`)だけが入っており、フロント(モードの切り替えと表示)は別 PR**
- **一括モード**(Issue #48、順番トグルで選ぶ)では、その周でまだ確定していないマス **全部** について「そのマスに入る数字」を1回でまとめて聞く。Worker の `ask:"all"`(4章)/ Claude の同種のスキーマ(4章「Claude 経路」)を使い、空マスごとの `choice`(1〜9 の確率つき)がまとめて返るので、**1 周につき API 呼び出しは 1 回**(左上からの 51 回、確信度順の約 102 回、数字ごとの最大 9 回と比べる数字)。**ただし Claude 経路はマス数が多いとスキーマサイズの都合でチャンク分割される**(既定 10 件ずつ。4章「Claude 経路」の「一括モードの1周ぶん」参照、Issue #74)。送る盤面は数字ごとモードと同様、**その周でまだ確定していないマスを `.` にしたスナップショット**(`buildSelectionSnapshot()`)にする。応答はその周の間だけ持つキャッシュ(`allResults`)に置き、周の先頭で1回呼んだあとは、既存の「フォーカス→バー表示→確定→次へ」の流れをマスごとに **fetch なしで** キャッシュから回す(1マス = 記録1件は従来どおり)。周が変わる・停止(手動・一時的な失敗)後の「再開」・リセット・新しい問題・エラーのそれぞれでキャッシュの扱いは異なる: 周が変わる・リセット/新しい問題・エラーでは空にする(次の周・実行はもう一度1回呼ぶ)。停止/再開ではキャッシュを保ち、再開はキャッシュにあるマスから続けて **再度呼ばない**(呼び出し自体の最中に停止した場合だけ、再開時にもう一度呼ぶ)。記録の `m` は `typesafe/jev/all`(Claude は `<既存のモデル識別子>/all`、例 `claude-opus-5+think/all`)、`o` は `"all"` になり、較正図のモデルフィルタで別項目として絞り込める。「現在の判定」パネルは呼び出し中「一括で判定中…(N マス)」、応答後は既存どおり各マスのバー表示。プロンプト枠は「一括」1段で、質問が空マスの数だけあり大きいので「質問 N 問」の要約 + 折りたたみで表示する。**実装済み**(Worker 側は Issue #48 の Worker 側 PR、フロントは本 PR)
- **消去法**(Issue #61「履歴」・#63「ルール候補」)。マスを聞くとき、Worker/Claude の候補(`exclude`。4章)から次の2種類の数字を外す。「消去法(履歴): あり」「ルール候補: あり」の2トグル(いずれも既定あり)で個別にオン/オフでき、実行中・停止中はロックする。フロントは次の2つの純粋関数の和集合だけから `exclude` を作る(それ以外の由来の除外は作らない。`docs/DESIGN.md` 9章 不変条件1)
  - **履歴**(`wrongDigits`、`"r-c"` → 外れた数字の配列): そのマスに **前の周までで** 入れて不正解だった数字(`commitFocused()` が不正解のたびに積む)。周をまたいで保持し、`reset()` / 「新しい問題」で空にする(停止/再開では保つ)
  - **ルール候補**(`ruleExclusions(r,c)`): そのマスの行・列・3×3ブロックに **既に埋まっている**(与えられたヒント + **前の周までに正解して確定した**マス)数字。**今の周の中の推測(正解・不正解問わず、まだ `queue` に残っている=未確定のマス)は含めない**。数独のルールだけを使い、**正解(`SOLUTION`)は一切見ない**。周の開始時点(初回開始時・各周の先頭)に1回だけ取るスナップショット `settledKeys`(`state.values` のキーから、その周の `queue` に入っているキーを除いたもの)を通して見るため、同じ周の中で先に確定した推測(不正解を含む)が他のマスの候補に混ざることはない(Issue #63 M1)。一括モードでも同様、`queue` のマスを `.` にする前の実盤面のうち `settledKeys` の分だけを見る
  - 昇順・重複なしの和集合が `exclude` になる。左上から/確信度順の数字判定(`judgeCellJev` / `judgeCellClaude`)は配列、一括(`askAllJev` / `askAllClaude`)はマスのキーごとの配列(空マスは省き、全部空なら `exclude` 自体を付けない)。マス選び(`ask:"cell"`)には付けない(Worker が 400 にする)
  - 履歴は「そのマスに入れて不正解だった数字」、ルール候補は「そのマスの正解になり得ない(行・列・ブロックで既に確定済みの)数字」なので、どちらもそのマスの正解を含まない。9個全部になる(=正解まで除外される)のは理論上起きないが、防御として履歴側を捨ててルール側だけにし、それでも9個なら空にする(Worker の「excludeで全部の数字を外すことはできません」400 を絶対に踏まない)
  - Jev の応答の `probabilities` は残りの数字だけで返るので、「現在の判定」パネルのバーは1〜9全部を描きつつ、外した数字は0%ではなく「×」(グレー、`class="bar excluded"`)で表示する。`pc` は残り候補の中での確率のまま記録する
  - 記録に `n`(候補の数。除外なしなら9)・`e`(履歴トグルの状態)・`rc`(ルール候補トグルの状態)が付く(JSON エクスポートにも出る)
  - Claude 経路はスキーマの `choice.enum` / `probabilities` のキーを残りの数字だけにし、`system` の末尾に「Digits already ruled out for a cell are omitted from its choices.」を1文添える(除外が無いときは従来どおりのプロンプトのまま変えない)

### F4. 速度モード

| モード | 確定前の待ち | 確定後の待ち | 周と周の間 |
|---|---|---|---|
| じっくり確認 | 700ms | 150ms | 250ms |
| 最速 | 0ms | 20ms | 80ms |

いずれもAPIの実レイテンシは別途乗る。「最速」は Jev の速度をそのまま体感するためのモード。

### F4'. 難易度モード(ヒント数)

「新しい問題」で生成する問題の目標ヒント数(与えられた数字の数)は難易度トグルで選ぶ。数字が少ないほど手がかりが減り、Jevにとって難しくなる。

| 難易度 | 目標ヒント数 |
|---|---|
| やさしい | 36 |
| ふつう(既定) | 30 |
| むずかしい | 25 |

「むずかしい」はジェネレーターの都合で目標ちょうどに届かず26〜28個で止まることがある(下限は24。`docs/DESIGN.md` 5章)。

### F5. エラー処理

- `/api/judge` が 2xx 以外、またはJSONでない、または `answers.digit` が無い場合はエラー扱い
- フロントは赤いエラーボックスに理由を表示し、`running=false` にして停止
- 停止後は **実行ボタンを無効化する**。復帰は **リセットのみ**で、盤面・周回ログ・統計をすべて捨てて **1周目の最初からやり直す**(途中から再開はしない。何周目のどのマスから再開すべきかが一意に決まらず、実験としての読み方も濁るため)
- **一時的な失敗(Issue #43)は上記のエラー扱いにせず、停止(Issue #32)扱いにする**。対象は Claude 経路の HTTP 429 / 529 / 5xx とネットワーク失敗(`fetch` が reject)、Jev 経路(Worker)の HTTP 429(レート制限)/ 503(カウンタ障害)。これらは `running=false` にはなるが `errorMessage` は立てず、盤面・周回ログ・統計・`queue` を保ったまま「停止中」(F2 の停止と同じ)になり、実行ボタンは「再開」のまま押せる。「再開」で続きから動かせる(判定中だったマスは F2 と同様にもう一度最初から聞き直す)。「現在の判定」パネルの「停止中」表示の下に、赤系の理由の箱(429 ならレート制限の残り秒数を含む文言)を添える(F1)。それ以外(400/401/415/502/形式不正・応答の検証失敗・APIキー未設定・選ばれたマスが候補に無い、など)は従来どおりこのエラー扱いで、復帰はリセットのみ
- リセットは進行中の判定があっても安全に行える。リセット時点で飛んでいる `/api/judge` の結果や予約済みのタイマーは、新しい盤面には一切反映しない(`docs/DESIGN.md` 4.3 の実行世代)
- **リセット時は進行中の `/api/judge` リクエストを中断する**(`AbortController`。結果を無視するだけでなく、リクエスト自体を打ち切って無駄な待ち時間とレート制限消費を減らす。`docs/DESIGN.md` 4.3、Issue #19)
- Worker 側は 400(入力不正)/415(`content-type` が `application/json` でない)/429(レート制限超過)/502(AI呼び出し失敗・予期しない形式)/503(レート制限のカウンタが記録できない)を返し、`error` フィールドに日本語の理由を入れる

### F6. レート制限

Workers AI の利用コストが青天井にならないよう、`/api/judge` に2段構えの固定ウィンドウ・レート制限をかける。

- **IP単位**: `CF-Connecting-IP` ごとに、**120回 / 3600秒(1時間)**(`wrangler.toml` の値。2026-09-22 にオーナー判断(Issue #20)で 30 から緩和。数独 1 問 ≈ 78 判定を 1 時間で完走できる値。コード側のフォールバックは 30)
- **全体**: 全アクセス合算で、既定 **500回 / 3600秒(1時間)**。IP単位の制限を分散アクセスで回避されても、これが最終防衛ラインになる
- どちらか一方でも超過したら **429** を返す。`error` に日本語の理由、`Retry-After` ヘッダーに残り秒数を入れる
- 上限値・ウィンドウ幅は `wrangler.toml` の `[vars]`(`RATE_LIMIT_PER_IP_MAX` / `RATE_LIMIT_GLOBAL_MAX` / `RATE_LIMIT_WINDOW_SECONDS`)で調整する。**コードを変更せず、値を書き換えて再デプロイするだけで調整できること**
- カウンタの保存先は **Durable Object**(クラス `RateLimitCounter`、バインディング名 `RATE_LIMITER`)。全体用に1インスタンス、IPごとに1インスタンスを使う。Durable Object はインスタンスが1つで直列実行なので、分散アクセスでも数え落としが起きない(当初は Workers KV を使っていたが、結果整合のため全体上限が分散アクセスに効かなかった。`docs/DESIGN.md` 3.2 / GitHub Issue #10)
- `RATE_LIMITER` バインディングが存在しない場合は、レート制限をかけずに通す(フェイルオープン)。ローカルの `wrangler dev` などバインディングを用意していない場合に動作を止めないため
- バインディングはあるのにカウンタの呼び出しが失敗した場合は、逆に **止める**(フェイルクローズ)。503 と `Retry-After: 60` を返す。回数を数えられない状態で Workers AI を呼ぶと上限が無くなるため
- 不正な入力(400)や AI 失敗(502)も回数に数える。415 とカウンタ障害(503)は数えない(レート制限より前で止まる、または数えられないため)

## 4. API 仕様

### `POST /api/judge`

リクエスト:

````json
{
  "puzzle": [
    "53..7....",
    "6..195...",
    ".98....6.",
    "8...6...3",
    "4..8.3..1",
    "7...2...6",
    ".6....28.",
    "...419..5",
    "....8..79"
  ],
  "target": { "row": 0, "col": 2 }
}
````

- `puzzle`: 9要素の文字列配列。各要素は9文字。文字は `1`〜`9` と `.`(未確定)のみ
- `target.row` / `target.col`: 0〜8 の整数
- `ask`(任意): `"digit"`(既定)/ `"cell"` / `"where"` / `"all"`。省略時は従来どおり `"digit"`。`"cell"` は「空マスのうち最も確定しやすいマスはどれか」を、`"where"` は「指定した数字がどの空マスに入るか」を、`"all"` は「残りの空マスそれぞれに入る数字」をまとめて聞くモードで、いずれも `target` を取らない(後述)
- `content-type` ヘッダーのメディアタイプ(`;` の前)が `application/json` であること(`charset` 等のパラメータは付いていてよい)。そうでなければ 415(レート制限より前に弾く。他サイトのページからの呼び出しを塞ぐため。`docs/DESIGN.md` 7章)
- 次のいずれかに当てはまる場合は 400: JSON でない / 上記の形式でない / `target` のマスが `.`(空)でない / `puzzle` の埋まっているマスが 17 個未満 / `ask` が `"digit"` `"cell"` `"where"` `"all"` 以外
- 盤面はブラウザ側のジェネレーターが作るので、Worker は特定の問題(初期配置)を持たない。どの問題から来たリクエストかは検証せず、「数独の盤面として受け付けられる形か」だけを見る
- 行・列・箱の矛盾は **検証しない**。過去の周の不正解の推測をそのまま残して送る設計なので(F3)、矛盾した盤面が来るのは正常な状態である
- 17 は一意解を持つ数独の最小ヒント数。これ未満の盤面は数独として成立しないので弾く
- `exclude`(任意。Issue #61「消去法」): `"1"`〜`"9"` の **文字列** の配列。前の周でそのマスに入れて不正解だった数字を渡すと、Jev の選択肢(`criteria`)から外して聞く。**送るのは外れた数字だけで、正解は送らない**(3章 F3・`docs/DESIGN.md` 9章 不変条件1)。同じマスに毎周同じ間違いを返し続けて15周の上限まで進まない、という状況を避けるためのもの
  - 例: `{ "puzzle": [...], "target": { "row": 0, "col": 2 }, "exclude": ["5", "3"] }` → `criteria` は `1 2 4 6 7 8 9`(昇順。`exclude` の並び順によらない)
  - 省略・空配列 `[]` は「1つも外さない」で、省略時とまったく同じ payload になる
  - 400: 配列でない(`null` を含む)/ 要素が `"1"`〜`"9"` の文字列でない(数値の `5`、`"0"`、`"10"` など)→ `"excludeは\"1\"〜\"9\"の文字列の配列である必要があります"`。同じ数字が2回 → `"excludeに同じ数字が重複しています"`。9個全部 → `"excludeで全部の数字を外すことはできません"`(少なくとも1つは残す。8個外して1つだけ残すのは可)
  - 検証の順番は `ask` → `puzzle` が9要素の配列 → `target` → 各行の形式 → **`exclude`** → `target` の範囲とマスが空 → 17個以上
  - 200 の形は変わらない。`probabilities` のキーは **残りの数字とちょうど一致**、`choice` は残りの数字のいずれか(外した数字を返してきたら、9キー全部を返してきた場合も含めて 502。文言は `exclude` があるときだけ「候補の数字(exclude後)とちょうど一致していません」/「候補の数字(exclude後)のいずれかではありません」になる。`exclude` が無いときは従来どおり)。`request` の `criteria` にも残りの数字だけが載る
  - レート制限は変わらない(1呼び出し = 1カウント)

レスポンス(200):

````json
{
  "probabilities": { "1": 0.03, "2": 0.05, "3": 0.02, "4": 0.61, "5": 0.08, "6": 0.07, "7": 0.04, "8": 0.06, "9": 0.04 },
  "choice": "4",
  "confidence": 0.31,
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "target": { "row": 0, "col": 2 }, "note": "..." },
    "questions": { "digit": { "type": "choice", "instructions": "...", "criteria": { "1": "the digit 1", "...": "..." } } }
  },
  "usage": { "input_tokens": 665, "output_tokens": 80 }
}
````

- `probabilities`: キーは `"1"`〜`"9"` の文字列、値は 0〜1(Jev の契約。Worker は有限の数値であることだけを検証し、範囲は検証しない)
- `choice`: Jev が選んだキー(文字列)
- `confidence`: Jev が返す独自の確信度。`probabilities[choice]` とは一致しない(実測: 0.20 に対して 0.10 など)。較正の検証には `probabilities` を使う
- `request`: `env.AI.run` に渡したペイロードそのもの。`state.puzzle` / `state.target` / `state.note` / `questions.digit.{type,instructions,criteria}`(フロントの「モデルに送ったプロンプト」パネルがそのまま表示する。Issue #34)。502 にも付く。400/415/429/503 には付かない(まだ payload を組み立てていないため)
- `usage`: Jev が返すトークン使用量(`input_tokens` / `output_tokens`)。コスト表示用に **200 にそのまま載せる**。`ask` の種類(`digit` / `cell` / `where` / `all`)によらず同じ形で付く
- ただし Jev の応答に `usage` が無い・オブジェクトでない・`input_tokens` / `output_tokens` が有限の数値でない場合は `usage` ごと **省略** する(参考情報なので 502 にはせず、判定結果の検証にも影響させない)。502 には付けない

#### `ask: "cell"`(マス選び。Issue #38)

「空マスのうち、どのマスが最も確定しやすいか(その数字を最も自信を持って言えるか)」を Jev の `choice` で聞くモード。確信度順モード(3章 F3)の1ステップ目に使う。

リクエスト:

````json
{
  "puzzle": ["53..7....", "6..195...", "..."],
  "ask": "cell"
}
````

- `puzzle` の形式チェック(9行×9文字、`1`〜`9` と `.`、埋まっているマスが17個以上)は `ask:"digit"` と同じ
- **`target` は取らない**。付いていたら 400(どちらのつもりのリクエストか曖昧にしないため、無視せず弾く)
- **`exclude` も取らない**(Issue #61)。付いていたら(`null` でも)400(`"ask:cellではexcludeを指定できません"`)。候補が数字ではなくマスなので
- 空マス(`.`)が1つも無ければ 400(聞くものが無い)
- Jev に渡す `criteria` は **空マスだけ** を行優先の順に並べたもの。キーは `"r" + row + "c" + col`(例 `"r0c2"`)、値は `"row 0, column 2 (zero-based)"`。Jev の `choice` は選択肢を255個まで取れるので、空マスは最大64個(埋まっているマスが17個以上という共通条件のため)なので1回で聞ける
- `state` は `{ puzzle, note }` のみ(`target` が無いぶん `note` も専用の文面)
- レート制限は `ask` によらず **1呼び出し = 1カウント**。確信度順モードは1マスあたり2回呼ぶので、その分だけ回数を消費する(3章 F6 の上限は据え置き)

レスポンス(200):

````json
{
  "probabilities": { "r0c2": 0.03, "r0c3": 0.01, "...": 0.0 },
  "choice": "r0c2",
  "confidence": 0.18,
  "cell": { "row": 0, "col": 2 },
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "note": "..." },
    "questions": { "cell": { "type": "choice", "instructions": "...", "criteria": { "r0c2": "row 0, column 2 (zero-based)", "...": "..." } } }
  },
  "usage": { "input_tokens": 700, "output_tokens": 90 }
}
````

- `probabilities`: キーは criteria のキー(空マスの一覧)と **ちょうど一致**(個数も各キーも)。値は有限の数値
- `choice`: 選ばれた空マスのキー。`cell` はそれを座標に分解したもの(フロントが毎回パースしなくて済むように添える)
- `confidence` / `request`: `ask:"digit"` と同じ意味
- `answers.cell` が無い / `probabilities` のキーが criteria と一致しない(余計なキー・欠け・キー名違い)/ `choice` が criteria のいずれでもない / `confidence` が数値でない、のいずれかなら 502(`raw` と `request` を添える)

#### `ask: "where"`(数字ごと。Issue #45)

「いま聞いている数字(`digit`)が、**どの空マスに入るか**」を空マスごとの `noul`(0〜1 の確率)でまとめて聞くモード。数独を解く人間の「4 はどこ?」という見方に対応する。**1回の `env.AI.run` に空マスの数だけ質問を入れる**(2026-09-22 に 51 個の質問を1回で投げて 51 件返ることを実環境で確認済み。`docs/DESIGN.md` 3.4)。

リクエスト:

````json
{
  "puzzle": ["53..7....", "6..195...", "..."],
  "ask": "where",
  "digit": "4"
}
````

- `puzzle` の形式チェック(9行×9文字、`1`〜`9` と `.`、埋まっているマスが17個以上)は `ask:"digit"` と同じ
- `digit`: `"1"`〜`"9"` の **文字列**。欠けている・数値(`4`)・範囲外(`"0"` / `"10"`)なら 400(`"ask:whereではdigitに1〜9の文字列を指定してください"`)
- **`target` は取らない**。付いていたら 400(`"ask:whereではtargetを指定できません(盤面全体に聞くため)"`)
- **`exclude` も取らない**(Issue #61)。付いていたら(`null` でも)400(`"ask:whereではexcludeを指定できません"`)。検証の位置は `digit` の直後
- 空マス(`.`)が1つも無ければ 400(聞くものが無い)
- 検証の順番は `ask` → `puzzle` が9要素の配列 → `target` 禁止 → `digit` → `exclude` 禁止 → 各行の形式 → 17個以上 → 空マスあり
- Jev に渡す `questions` は **空マス1つにつき1問**(`type: "noul"`)。キーは `ask:"cell"` と同じ `"r" + row + "c" + col` で、並びは行優先。各問の `instructions` は `WHERE_INSTRUCTIONS_TEMPLATE`(`"Is the digit {digit} the one that belongs in the empty cell at row {row}, column {col} (zero-based)?"`)に座標と数字を埋めたもの
- `state` は `{ puzzle, digit, note }`(`target` は無く、`note` は専用の文面 `WHERE_NOTE`)
- レート制限は `ask` によらず **1呼び出し = 1カウント**。空マス51個ぶんを1回で聞くので、盤面1つあたり1カウントで済む

レスポンス(200):

````json
{
  "probabilities": { "r0c2": 0.24, "r0c3": 0.02, "...": 0.0 },
  "digit": "4",
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "digit": "4", "note": "..." },
    "questions": { "r0c2": { "type": "noul", "instructions": "Is the digit 4 the one that belongs in the empty cell at row 0, column 2 (zero-based)?" } }
  },
  "usage": { "input_tokens": 1948, "output_tokens": 973 }
}
````

- `probabilities`: キーは質問キー(空マスの一覧)と **ちょうど一致**(個数も各キーも)。値は各マスの `noul` をそのまま通したもの
- **`choice` / `confidence` / `cell` は付かない**。`noul` の回答は確率だけで、選択も確信度も持たないため(`docs/DESIGN.md` 3.4)。どのマスにするかの判断はアプリ側で行う
- `digit`: 聞いた数字をそのまま返す(応答だけ見てどの数字の問い合わせか分かるように)
- `request`: `ask:"digit"` と同じ意味(`env.AI.run` に渡したペイロードそのもの)
- `answers` が取り出せない / AI Gateway の `state` が `"Completed"` でない / `answers` のキーが質問キーと一致しない(余計なキー・欠け・キー名違い)/ いずれかの `noul` が有限の数値でない、のいずれかなら 502(`raw` と `request` を添える)。`type` は見ない

#### `ask: "all"`(一括。Issue #48)

「残りの空マスそれぞれに、**どの数字が入るか**」を空マスごとの `choice`(1〜9)でまとめて聞くモード。1 周ぶんを1回の呼び出しで済ませる。**1回の `env.AI.run` に空マスの数だけ質問を入れる**(2026-09-22 に空マス 51 個ぶんの `choice` 質問を1回で投げて 51 件返ることを実環境で確認済み。1,097 ms、入力 9,483 / 出力 4,083 トークン。`docs/DESIGN.md` 3.4)。

リクエスト:

````json
{
  "puzzle": ["53..7....", "6..195...", "..."],
  "ask": "all"
}
````

- `puzzle` の形式チェック(9行×9文字、`1`〜`9` と `.`、埋まっているマスが17個以上)は `ask:"digit"` と同じ
- **`target` は取らない**。付いていたら 400(`"ask:allではtargetを指定できません(残りの全マスに聞くため)"`)
- **`digit` も取らない**。付いていたら 400(`"ask:allではdigitを指定できません"`。`ask:"where"` と取り違えたリクエストを黙って別の質問として飛ばさないため)
- 空マス(`.`)が1つも無ければ 400(聞くものが無い)
- `exclude`(任意。Issue #61「消去法」): **マスのキーごと** の「外す数字」のオブジェクト。例 `{ "r0c2": ["4"], "r1c0": ["2", "7"] }`
  - キーは盤面の **空マス** のキー(`"r" + row + "c" + col`)でなければ 400(`"ask:allのexcludeのキーは盤面の空マス(\"r0c2\"形式)である必要があります"`。埋まっているマス・形式違い・範囲外)
  - オブジェクトでない(配列・`null`・文字列)なら 400(`"ask:allのexcludeはマスのキー(\"r0c2\")ごとの配列を持つオブジェクトである必要があります"`)
  - 各値の規則と 400 の文言は `ask:"digit"` の `exclude` と同じ(配列・`"1"`〜`"9"` の文字列・重複なし・9個全部は不可)。空配列のマスは無視(1〜9 のまま)。空オブジェクト `{}` は省略と同じ
  - `exclude` のあるマスの質問だけ、`criteria` が残りの数字だけの別オブジェクトになる。それ以外のマスは従来どおり共通の 1〜9
  - 応答の検証もマスごと: `exclude` のあるマスは `probabilities` が残りの数字とちょうど一致・`choice` がそのいずれか、それ以外のマスは 1〜9(不一致なら 502。文言はマスのキー付きの従来の文言)
- 検証の順番は `ask` → `puzzle` が9要素の配列 → `target` 禁止 → `digit` 禁止 → 各行の形式 → `exclude` → 17個以上 → 空マスあり(`cell` / `where` に揃えてある)
- Jev に渡す `questions` は **空マス1つにつき1問**(`type: "choice"`)。キーは `ask:"cell"` / `ask:"where"` と同じ `"r" + row + "c" + col` で、並びは行優先。各問の `instructions` は `ALL_INSTRUCTIONS_TEMPLATE`(`"Which digit from 1 to 9 belongs in the empty cell at row {row}, column {col} (zero-based)?"`)に座標を埋めたもの、`criteria` は `ask:"digit"` と同じ `{ "1": "the digit 1", …, "9": "the digit 9" }`(`exclude` のあるマスは残りの数字だけ。上記)
- `state` は `{ puzzle, note }` のみ(`target` も `digit` も無く、`note` は専用の文面 `ALL_NOTE`)
- 1回の呼び出しに入る質問は空マスの数だけ(埋まっているマスが17個以上という共通条件から **最大64問**、1問あたり criteria は9個)。実環境で確認済みなのは51問まで(2026-09-22、`docs/DESIGN.md` 3.4)で、64問は未検証
- レート制限は `ask` によらず **1呼び出し = 1カウント**。1 周ぶんを1回で聞くので、周1つあたり1カウントで済む

レスポンス(200):

````json
{
  "cells": {
    "r0c2": { "choice": "4", "probabilities": { "1": 0.03, "...": 0.0, "9": 0.04 }, "confidence": 0.31 },
    "r0c3": { "choice": "6", "probabilities": { "...": 0.0 }, "confidence": 0.12 }
  },
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "note": "..." },
    "questions": {
      "r0c2": { "type": "choice", "instructions": "...", "criteria": { "1": "the digit 1", "...": "..." } }
    }
  },
  "usage": { "input_tokens": 9483, "output_tokens": 4083 }
}
````

- `cells`: キーは質問キー(空マスの一覧)と **ちょうど一致**(個数も各キーも)し、並びは行優先。値は `ask:"digit"` の 200 と同じ `{ choice, probabilities, confidence }`(`type` は落とす)
- `probabilities` は `"1"`〜`"9"` の9キー、`choice` はそのいずれか、`confidence` は Jev の値をそのまま(`probabilities[choice]` とは一致しない)。検証の基準は `ask:"digit"` と同じものをマスごとに当てる
- **`choice` / `confidence` / `probabilities` / `cell` / `digit` はトップレベルには付かない**(マス単位に返すため)
- `request`: `ask:"digit"` と同じ意味(`env.AI.run` に渡したペイロードそのもの)
- `answers` が取り出せない / AI Gateway の `state` が `"Completed"` でない / `answers` のキーが質問キーと一致しない(余計なキー・欠け・キー名違い)/ いずれかのマスの回答が `ask:"digit"` の基準を満たさない、のいずれかなら 502(`raw` と `request` を添える)。マス単位の不備は **どのマスで落ちたか** が分かる文言になる(`"r0c2 の応答のprobabilitiesが1〜9の9キーになっていません"` など)

エラー(400 / 415 / 429 / 502 / 503):

````json
{ "error": "puzzle(9行の配列)とtarget({row,col})が必要です" }
````

429の例:

````json
{ "error": "アクセス元(IP)ごとのレート制限(120回/3600秒)を超えました" }
````

429 のレスポンスヘッダーには `Retry-After`(秒)と `X-RateLimit-Scope`(`ip` または `global`)を、503 には `Retry-After: 60` を付ける。`X-RateLimit-Remaining-IP` / `X-RateLimit-Remaining-Global` は **レート制限を通過したレスポンスすべて**(200 のほか 400 や 502 も。いずれも1回として数えているため)に付く。レート制限より手前で止まる 415 と、制限に引っかかった 429 / 503 には付かない。`RATE_LIMITER` バインディングが無いフェイルオープン時も、残数が存在しないので付かない。

200 を返すのは Jev の回答が期待どおりの形だったときだけ。`answers.<ask>`(`digit` / `cell`)が無い、AI Gateway の `state` が `"Completed"` でない、`probabilities` のキーが期待する集合(`digit` なら `"1"`〜`"9"` の9個、`cell` なら criteria のキー)とちょうど一致しない、値が数値でない、`choice` がそのいずれでもない、`confidence` が数値でない、のいずれかなら 502 とし、`raw` に受け取った生レスポンスを添える。`ask:"where"` は `answers` そのもの(質問キーの集合と各 `noul`)を、`ask:"all"` は `answers` そのもの(質問キーの集合と、各マスについて `digit` と同じ基準)を検証する。`answers` は実環境ではラッパーの中(`result.answers`)に入っている(`docs/DESIGN.md` 3.4)。

### `GET /api/status`

レート制限の残り回数を **読むだけ** で返す(7章の拡張5の最小版)。カウンタは `peek` でしか触らないので、この呼び出し自体は回数に数えられず、残数も減らない。

レスポンス(200):

````json
{
  "window_seconds": 3600,
  "resets_in": 1847,
  "global": { "max": 500, "used": 34, "remaining": 466 },
  "ip": { "max": 30, "used": 6, "remaining": 24 }
}
````

- `window_seconds` / `global.max` / `ip.max`: `wrangler.toml` の `[vars]` の値(`/api/judge` と同じ読み方)
- `resets_in`: 現在の固定ウィンドウが終わるまでの秒数(429 の `Retry-After` と同じ式)
- `ip`: 呼び出し元の `CF-Connecting-IP`(無ければ `unknown`)の分
- `remaining` は `max(0, max - used)`
- `Cache-Control: no-store` を付ける(残数は数秒で変わる)。CORS ヘッダーは付けない
- `RATE_LIMITER` バインディングが無い(フェイルオープン中)ときは、数えていないので残数も無い。200 で `{ "rate_limit": "disabled" }` を返す
- カウンタの呼び出しが失敗したときは 503 と `Retry-After: 60`(`/api/judge` のフェイルクローズと同じ扱い): `{ "error": "レート制限の状態を取得できません" }`
- `GET` のみ。`POST /api/status` は 404

### `GET /`

フロントエンド一式(HTML)を `text/html; charset=utf-8` で返す。それ以外のパスは 404。CORS ヘッダーは付けない(他サイトから `/api/judge` を呼ばせない)。

### `GET /compare`(比較モード、Issue #46)

`GET /` と**まったく同じ** `PAGE_HTML`(セキュリティヘッダーも同じ)を返す。差は「比較シェルを描くかどうか」だけで、フロント側が `location.pathname === "/compare"` を見て分岐する(3章 F1'、`docs/DESIGN.md` 3.1・4.2)。`GET` 以外は 404。

### Claude 経路(ブラウザ → `https://api.anthropic.com/v1/messages`、Worker は関与しない)

モデルが「Claude」のときの 1 判定。Worker を経由せず、ブラウザが Anthropic Messages API を直接呼ぶ(7章 拡張3、Issue #37。`docs/DESIGN.md` 3.6)。

- ヘッダー: `content-type: application/json` / `x-api-key: <利用者のキー>` / `anthropic-version: 2023-06-01` / `anthropic-dangerous-direct-browser-access: true`(ブラウザからの直接呼び出しに必要)
- ボディ(= 画面の「モデルに送ったプロンプト」に出るもの。キーは含まれない):

````json
{
  "model": "claude-opus-5",
  "max_tokens": 16000,
  "system": "<Jev と同じ NOTE> Answer with JSON only, matching the given schema: ...",
  "messages": [{ "role": "user", "content": "Which digit from 1 to 9 belongs in the target cell of this Sudoku grid?\n{\"puzzle\":[...9行...],\"target\":{\"row\":0,\"col\":2}}" }],
  "output_config": { "format": { "type": "json_schema", "schema": { "...": "choice(1〜9) / probabilities(1〜9 の 9 キー) / confidence" } } },
  "thinking": { "type": "adaptive" }
}
````

- `thinking`: 思考ありなら `claude-opus-5` / `claude-sonnet-5` は `{ "type": "adaptive" }`(このとき `max_tokens` は 16000。思考トークンも `max_tokens` に含まれるため)、`claude-haiku-4-5` は `{ "type": "enabled", "budget_tokens": 2048 }`(このとき `max_tokens` は 2048 + 1024)。思考なしなら Opus / Sonnet は `{ "type": "disabled" }`、Haiku は `thinking` を送らない(`max_tokens` は 1024)
- 「キーを消す」は実行中・停止中は押せない(次のマスで止まってしまうため)。キー保存の失敗は判定ループを止めず、設定パネル内の注意書きに出す
- 応答: `content` の最初の `text` ブロックが structured outputs の JSON(`{ "choice": "4", "probabilities": { "1": 0.03, ... }, "confidence": 0.7 }`)。検証は `/api/judge` の 200 と同じ基準(9 キー・有限数・`choice` が 1〜9・`confidence` が数値)。`stop_reason` が `refusal` / `max_tokens`、HTTP が非 2xx(401 キー不正、429、529 など)、ネットワーク失敗は F5 のエラー扱い(理由をエラーボックスに出して停止)
- `probabilities` / `confidence` は **Claude の自己申告**であり較正されている保証はない。それを Jev の値と同じ較正図で比べるのがこの拡張の目的
- レート制限(F6)は関与しない(利用者自身のキーと課金)

#### 確信度順モードのマス選び(Issue #38)

確信度順モード(3章 F3)で Claude をモデルに選んでいるときのマス選び1回ぶん。数字判定と同じ経路・同じ思考(thinking)の規則を使うが、`system` / `messages` / スキーマがマス選び用になる。

````json
{
  "model": "claude-opus-5",
  "max_tokens": 16000,
  "system": "<Jev と同じ CELL_NOTE> Answer with JSON only, matching the given schema: ...",
  "messages": [{ "role": "user", "content": "Which empty cell of this Sudoku grid can be filled in with the most certainty?\n{\"puzzle\":[...9行...]}" }],
  "output_config": { "format": { "type": "json_schema", "schema": { "...": "choice(候補キーの enum) / probabilities(候補キー全部が required) / confidence" } } },
  "thinking": { "type": "adaptive" }
}
````

- `system` は Worker の `CELL_NOTE`(`ask:"cell"` の `note` と同じ文字列)+ digit 判定と同じ「JSON で答えよ」の指示文。`messages[0].content` は Worker の `CELL_INSTRUCTIONS` + 改行 + `{ puzzle }`(`target` は無い。盤面は `buildSelectionSnapshot()`)
- スキーマの `choice` は `enum` にその時点の `queue` のマスのキー(`"r" + row + "c" + col`、行優先)を並べたもの、`probabilities` はそのキー全部を `properties` / `required` に持ち `additionalProperties: false`。`confidence` は数値。呼び出しのたびに候補(= `queue`)が変わるので、毎回組み立て直す
- 応答の検証は「`probabilities` のキーが候補キーとちょうど一致・`choice` が候補キーのいずれか・`confidence` が有限数」(digit 判定の検証を候補キー集合に一般化したもの)。`choice`(`"r0c2"` 形式)は正規表現 `/^r(\d)c(\d)$/` で座標に分解する
- `thinking` / `max_tokens` の規則は数字判定と同じ

#### 一括モードの1周ぶん(Issue #48)

一括モード(3章 F3)で Claude をモデルに選んでいるときの、周の先頭ぶん。`queue` の全マス(その周でまだ確定していないマス)について、マスごとの `{ choice, probabilities, confidence }` を structured outputs でまとめて受け取る。

**チャンク分割(Issue #74)**: マス数が多いと、1つのスキーマに入れ子オブジェクトがマス数ぶん並ぶため、Anthropic の構造化出力が「compiled grammar is too large」で 400 を返すことが実機で確認された。`askAllClaude()` は `queue` を `CLAUDE_ALL_CHUNK_SIZE`(既定 10)件ずつのチャンクに区切り、チャンクごとに独立したリクエスト(スキーマの `properties`/`required` もそのチャンクのキーだけ)を**並列に**呼んでから結果をマージする(同じ `AbortController` を共有するので、停止すれば全チャンクまとめて中断される)。usage はチャンクぶんを合算して1件の `{ input_tokens, output_tokens, cache_read_input_tokens? }` にし、記録への付け方(周の先頭1件だけ)は従来どおり変えない。プロンプト枠には先頭チャンクの1件だけを表示し、「(N回に分割。先頭の1回だけ表示)」を添える(失敗時は実際に失敗したチャンクを表示し「失敗した1回を表示」)。1周1回という設計上の利点は薄まるが(51マスの固定問題で既定なら6回)、左上から(51回)・確信度順(約102回)と比べれば依然として少ない。Jev 経路(Worker、`ask:"all"`)はこの制約と無縁なので変更していない。

一部のチャンクだけ失敗しても、成功していたチャンクぶんの usage は捨てずに持ち越す(`carryUsage`、5章の「画面のコスト表示」参照)。ただし停止/再開はその周をもう一度全チャンク呼び直すので、成功していたチャンクぶんが実際に二重課金されること自体は避けられない(既知の制約)。また、チャンクは互いに独立して答えるため、**「同じ行に同じ数字を2回選ばない」といったチャンクをまたぐ一貫性は保証されない**(1チャンクに収まる問題ではモデルが応答全体を見て整合させられるが、チャンク分割後は各チャンクが他チャンクの答えを見ずに独立して答える)。マス数が `CLAUDE_ALL_CHUNK_SIZE` 以下(チャンク1個)の問題と、それを超える問題とで、この点は条件が異なる。

````json
{
  "model": "claude-opus-5",
  "max_tokens": 24000,
  "system": "<Jev と同じ ALL_NOTE> Answer with JSON only, matching the given schema: for each cell key, ...",
  "messages": [{ "role": "user", "content": "Which digit from 1 to 9 belongs in each empty cell of this Sudoku grid? Answer for every cell key required by the schema (...).\n{\"puzzle\":[...9行...]}" }],
  "output_config": { "format": { "type": "json_schema", "schema": { "...": "候補キー(r0c2 など)それぞれが required で、各値は digit 判定と同じ { choice(1〜9 の enum) / probabilities(1〜9 が required) / confidence }" } } },
  "thinking": { "type": "adaptive" }
}
````

- `system` は Worker の `ALL_NOTE`(`ask:"all"` の `note` と同じ文字列)+「マスごとに choice / probabilities / confidence の3つ組を JSON で答えよ」の指示文(`CLAUDE_ALL_SYSTEM`)。`messages[0].content` は一括専用の1本の質問文(`CLAUDE_ALL_INSTRUCTIONS`。Worker の `ALL_INSTRUCTIONS_TEMPLATE` はマス1つぶんの文言なので使わない。対象マスの一覧はスキーマの required キーそのもの)+ 改行 + `{ puzzle }`(`target` は無い。盤面は `buildSelectionSnapshot()`)
- スキーマはその時点の `queue` のマスのキー(`"r" + row + "c" + col`、行優先)をそれぞれ `properties` / `required` に持つオブジェクト(`additionalProperties: false`)で、各値は digit 判定と同じ形。呼び出しのたびに候補が変わるので毎回組み立て直す
- 応答の検証は「キー集合が候補キーとちょうど一致(余分・欠けはエラー停止)・各マスは digit 判定と同じ基準」。`stop_reason` が `max_tokens` / `refusal` のときも digit 判定と同じくエラー停止(一時的な失敗ではない)
- `thinking` の規則は数字判定と同じだが、**`max_tokens` には一括専用の下限がある**(出力が最大 64 マス × 9 確率の JSON になるため): 思考なし 16000 / adaptive 24000 / Haiku(`budget_tokens` 2048)12000 と、数字判定の値との大きい方。**この値で足りるかは実キー未検証**(`docs/DESIGN.md` 3.6)

## 5. 非機能要件

- **1ファイル**: Worker本体・フロントを `src/index.js` 1つに収める。ビルド不要
- **秘密情報を持たない**: APIトークン等はリポジトリに含めない。Workers AI の認証はバインディング経由。Claude 経路の API キーは利用者のブラウザ(`localStorage`)にだけあり、Worker にもリポジトリにも無い(4章「Claude 経路」)
- **コスト**: Jev は入力$0.042/100万トークン・出力無料。**Workers AI のニューロンではなく AI Gateway のクレジットで課金される**(`typesafe/jev` は AI Gateway 経由で提供されている。`docs/DESIGN.md` 3.4)。1問51マス×数周で誤差程度
- **レイテンシ**: Jev 公称 100ms 前後だが、**Worker 経由の実測は 1.0〜1.7 秒**(2026-09-21)。AI Gateway を挟む分の往復が乗る。最速モードで体感できるのはこの実測値のほう
- **認証なし・レート制限あり**: 公開デモとして誰でもアクセス可。ログイン等は無いが、F6のレート制限でコストの上限を確保する
- **CSP と埋め込み**(Issue #46): `GET /` `GET /compare` の `Content-Security-Policy` は `frame-ancestors 'self'`(同一オリジンの iframe にだけ埋め込みを許可)。比較モード(`/compare`、3章 F1')が自分自身を `<iframe>` で2枚埋め込むため、他サイトからの埋め込みは禁止したまま(`'none'` ではなく)`'self'` に緩めた。埋め込み先(`embed=1`)は親からの `message` を `event.origin` が同一オリジンのときだけ受け付ける
- **テスト可能**: `npm test`(Node 標準の `node:test`)で、Cloudflare の認証なしに Worker のロジックを検証できる。CI(GitHub Actions)で自動実行する
- **コスト**(2026-09-21 の実測トークン数にもとづく試算。1ドル=150円換算):
  - 1回の判定(実測 約670入力トークン): 約$0.000028(0.0042円)
  - 数独1問フル実行(51マス×平均3周≈78回): 約$0.0022(0.33円)
  - 全体上限(既定500回/時)に24時間張り付いた場合の理論上の最悪値: 約$0.34/日、月$10程度
  - `ask:"where"`(数字ごと、#45)は 1 回で入力 約1,950 / 出力 約970 トークン(空マス51個の実測。`docs/DESIGN.md` 3.4)と `digit` の約3倍。レート制限は回数でしか数えないので、全体上限に張り付いた最悪値は約 $1/日 になる(それでも小さいので上限は据え置き)
  - `ask:"all"`(一括、#48)は 1 回で入力 約9,483 / 出力 約4,083 トークン(空マス51個の実測。`docs/DESIGN.md` 3.4)。**1 周 1 回なので回数は最少**だが、1 回の単価は `digit` の約14倍。全体上限(500回/時)に24時間張り付いた最悪値は約 $4/日(それでも小さいので上限は据え置き)。**これは Jev 経路(Worker)の実測値。Claude 経路はチャンク分割(Issue #74)されるため、チャンクごとに盤面全体と説明文を送り直すぶん入力トークンが増える**(51マスの固定問題・既定のチャンクサイズ10なら入力トークンがおおむね6倍。Worker のレート制限には乗らない経路なのでコスト面の影響のみ)。また6リクエストが同時に飛ぶため、Anthropic 側のレート制限に近いキーでは 429 を踏みやすくなる可能性がある
- **確信度順モードは1マスあたりAPI呼び出しが2回**(マス選び+数字。Issue #38、3章 F3)。左上からモードの2倍のコスト・レート制限消費・所要時間になる(F6のIP単位上限120回/時に対して、確信度順で1問(51マス×平均3周)を完走するには単純計算で約156回かかり、1時間では収まらないことがある。急ぐ場合は左上からモードを使う)
- **画面のコスト表示(Issue #56)**: 記録(F1 拡張2、`localStorage` の `scc.records.v1`)は判定1件ごとに `u: { i, o }`(入力/出力トークン数。`ci` はキャッシュ読み込みトークン、あれば)と `t`(ミリ秒。その呼び出しのレイテンシ)を持つ。Jev は 200 の `usage.input_tokens` / `usage.output_tokens`(4章。無ければ `u` ごと付けない)、Claude は応答の `usage.input_tokens` / `usage.output_tokens` / `usage.cache_read_input_tokens`(あれば `ci`)をそのまま使う。**一括モード**(#48)は1回の応答で周ぶんの記録が生まれるので、周の記録のうち**先頭1件にだけ** `u` / `t` を付ける(二重計上しない)。**確信度順モード**(#38)はマス選び+数字の2回の呼び出しなので、両方の `usage` を足し合わせて数字判定の記録に付ける。**停止で中断した in-flight の呼び出しぶん(応答が届く前に abort したもの)はトークン数が分からないのでコストに入らない**。応答が届いていて確定前に停止したぶん(確信度順のマス選び・数字判定の待ち中の停止)は持ち越して次に確定する記録に足す
  - **単価**(100万トークンあたり USD)の既定値: Jev(`typesafe/jev`)入力 `0.042` / 出力 `0`(無料)、`claude-opus-5` 入力 `5` / 出力 `25`、`claude-sonnet-5` 入力 `2` / 出力 `10`(claude.com/pricing、2026-09-23 確認)、`claude-haiku-4-5` 入力 `1` / 出力 `5`。思考の有無は単価に影響しない(思考トークンは `output_tokens` に含まれる)。設定パネル(F1)の「単価」で上書きでき、`localStorage`(`scc.prices.v1`)に保存する。不正値(数値でない・負)は既定値にフォールバックする
  - **記録1件のコスト**(`costOf(rec)`): `(u.i * 入力単価 + ci * 入力単価 * 0.1 + u.o * 出力単価) / 1e6`(キャッシュ読みは入力単価の10%)。単価を引くモデルは記録の `m` から `/all`(一括)・`+think`(Claude の思考あり)の接尾辞を外したもの(例 `typesafe/jev/all` → `typesafe/jev`、`claude-opus-5+think` → `claude-opus-5`)。単価が見つからないモデルは 0 として扱い、表示に「(単価未設定)」を添える。`u` の無い記録は 0
  - **表示の書式**(`formatUsd`): `$` + 有効数字2桁程度。`$0.01` 以上は小数4桁まで(末尾0は削る。例 `$0.012`)、それ未満は例 `$0.00003` / `$0.0004`。0 は `$0`
