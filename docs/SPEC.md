# 仕様書 — 数独キャリブレーションチェック

最終更新: 2026-09-21 / 対象バージョン: v0.1

## 1. 目的と背景

TypeSafe AI の **Jev** は「文章を生成せず、型付きの判断を較正された確率つきで返す」モデルとして2026-09-15に公開された。公開ベンチマークが意図的に出されておらず、「確率が本当に較正されているか」を第三者が検証する手段がほぼない。

数独は **唯一の正解が機械的に確定できる** 珍しい題材である。「このマスは5である確率は?」という問いに対して、Jevが返した確率と実際の正解を突き合わせれば、Jevの主張を自分の目で確かめられる。本アプリはそのための実験装置であり、同時に「Jevに向いていないとされる System 2 タスク(多段階の論理推論)を、文脈を増やした反復でどこまで補えるか」を観察する装置でもある。

ゴールは「数独をJevで解くこと」ではない。**Jevの確率の信頼性を可視化すること**。

## 2. 用語

| 用語 | 意味 |
|---|---|
| Jev | TypeSafe AI の System One モデル。Cloudflare Workers AI では `typesafe/jev` |
| Choice | Jev のプリミティブの1つ。定義した選択肢から1つ選び、全選択肢の確率を返す |
| Noul | 真偽を 0〜1 の確率で返すプリミティブ(本アプリでは未使用、将来の転用先) |
| state | Jev に渡す判断対象。文字列・オブジェクト・配列のいずれか |
| 周(round) | 未確定マス全部を1回ずつ判定する1サイクル |
| スナップショット | 「与えられた数字 + それまでの周で埋まった推測(正誤問わず)」を9行の文字列で表した盤面 |

## 3. 機能要件

### F1. 画面構成

1画面構成。左に数独グリッド、右に判定パネル。

- **速度切り替え**: 「じっくり確認」「最速」の2択トグル。実行中でも切り替え可能
- **難易度切り替え**: 「やさしい」「ふつう」「むずかしい」の3択トグル(既定「ふつう」)。ヒント数(与えられた数字の数)を切り替える。変えただけでは盤面は変わらず、次の「新しい問題」から効く
- **モデル切り替え**: 「Jev」「Claude」の2択トグル(既定「Jev」)。実行中・停止中(周の途中)は切り替えられない(1周の中でモデルが混ざると周回ログの意味が崩れるため)。選択は `localStorage`(`scc.claude_settings.v1`)に保存され、次回開いたときも同じ
- **順番切り替え**(Issue #38): 「左上から」「確信度順」の2択トグル(既定「左上から」)。モデル切り替えと同じ条件で実行中・停止中はロックする(周の途中で選び方が混ざると周回ログの意味が崩れるため)。選択は `localStorage` には保存せず、実行中の `state` としてのみ `reset()` / 「新しい問題」をまたいで保持する(F3)
- **Claude の設定パネル**(モデルが「Claude」のときだけ表示。7章 拡張3、Issue #37): API キーの入力欄(`type=password`)と「保存」「キーを消す」ボタン、保存状態(未設定 / 保存済み(末尾 4 文字))、モデル選択(`claude-opus-5`(既定)/ `claude-sonnet-5` / `claude-haiku-4-5`)、思考(extended thinking)の「思考あり」「思考なし」トグル。キーは **このブラウザの `localStorage`(`scc.anthropic_key.v1`)にだけ保存し、`api.anthropic.com` への呼び出し以外には送らない**(Worker には渡らない)。キーの値そのものは画面に出さない
- **実行 / リセット / 新しい問題** ボタン
  - 「実行」ボタン(`id="run-btn"`)は実行中だけ**「停止」に切り替わる**(押すと止まる)。停止中(実行を始めた後、止めていて、完了もエラーもしていない状態)は**「再開」**になり、押すと続きから動く(F2/F3)。「リセット」「新しい問題」は停止中も押せる
  - 「リセット」は **現在の問題をやり直す**(盤面・周回ログ・統計を捨てて1周目の最初から)
  - 「新しい問題」はジェネレーターで別の問題を作って差し替える(ソルバーで一意解を確認済み)。生成中はボタンが「生成中…」になり、実行中と生成中は押せない。初期表示は Wikipedia の固定問題
- **数独グリッド**(9×9、3×3の区切り線を太くする)
  - 与えられた数字: 白・太字
  - 未判定: 空白
  - 判定中(フォーカス): アクセント色の枠線(inset)
  - 正解: 緑の数字と薄い緑背景
  - 不正解: 赤の数字と薄い赤背景
  - **確信度順モードのヒートマップ**(Issue #38): マス選びの直後、選ばれなかった候補マス(未判定・非フォーカス)の背景をアクセント色の薄い塗り(`rgba(125, 211, 252, α)`、`α = 0.08 + 0.6 * p / pmax`。`p` はそのマスがマス選びで選ばれる確率、`pmax` は候補内の最大値)で示す。選ばれたマス(フォーカス)は従来どおり枠線。数字が確定したら消える(次のマス選びまで出ない)。**2周目以降の候補マスは前の周の不正解の数字(赤背景)を持つので、ヒートマップは事実上1周目だけ出る**(赤/緑の意味を優先し、上に重ねない。パネルの「マス選び: N 候補中 …(p%)」で選ばれたマスの確率は周によらず読める)
- **統計カード**(4つ): 現在の周 / 残りマス / 累計正解 / この周の進捗
- **現在の判定パネル**: 判定中マスの座標(「3行目 6列目」形式)と、1〜9の横棒グラフ(確率%)。`choice` の棒だけアクセント色(`choice` は必ずしも argmax ではない。`docs/DESIGN.md` 3.4)。結果を待っている間・確定直後は、直前に確定した判定(座標・選んだ数字・正誤・確率バー)を次の結果が来るまで残す(最速モードでも見えるように)。**停止中は「停止中(残り N マス)」を表示し、フォーカスの枠線は消える**(F2)。**確信度順モード**(Issue #38): マス選び中は「マス選び中…(候補 N マス)」、マス選びが終わってから数字が確定するまでは、座標・バーの先頭に「マス選び: N 候補中 r行目c列目(p%)/ confidence q%」を添える
- **モデルに送ったプロンプト**: 直近の判定で Worker が Jev に渡したペイロード(`request`)、または Claude 経路ならブラウザが `api.anthropic.com` に送ったリクエストボディ(ヘッダーは含めない = キーは出ない)を JSON で表示し、対象マス(「N行目 M列目 の判定に使用」)を添える。判定が 502 で失敗したときはその `request` を「(このプロンプトで失敗)」付きで表示する。まだ無ければその旨。停止中・エラー中も残り、リセット/新しい問題で消える。**確信度順モード**(Issue #38): 「マス選び」見出し + マス選びに使ったリクエスト、続けて「数字」見出し + 従来どおりの数字判定のリクエストを2段で表示する
- **凡例**: 正解・不正解・判定中の色の意味。確信度順モードのときだけ「背景の濃さ = マス選びの確率」を1項目足す
- **周回ログ**: 「N周目: M中K正解 (P%)」を周ごとに追記
- **集計パネル(較正図)**: 周回ログの下に、これまでの判定結果(複数問題・複数回の実行をまたいでブラウザの `localStorage` に蓄積したもの)を集計して表示する(7章 拡張2)
  - 上部に合計件数・全体正解率・記録している問題数(ユニークな問題ID)
  - `pc`(`choice` の確率)と `conf`(モデルの `confidence`)それぞれで10%刻み10帯に分けた較正図(インラインSVGの棒グラフ、横並び。理想は対角線)を並べる。帯ごとに件数と実際の正解率を示す
  - **モデルのフィルタ**(`<select>`): 「すべて」か、記録に現れるモデル識別子(`typesafe/jev` / `claude-opus-5+think` など。記録の `m`。`m` の無い古い記録は `typesafe/jev` 扱い)を選び、そのモデルの記録だけを集計する(Jev と Claude の較正を並べて比べるため。Issue #37)
  - 「JSONエクスポート」ボタン: 蓄積した記録一式を `sudoku-calibration-YYYYMMDD-HHMMSS.json` としてダウンロードする
  - 「記録を消す」ボタン: 確認ダイアログのあと、蓄積した記録をすべて削除する
- **完了バナー**: 全マス正解時に「N周ですべて正解しました」
- **強制終了バナー**: 15周の安全弁(F3)で止まったときに「15周で強制終了しました(全マス正解には至りませんでした)」。周回ログの各行に残る不正解数と合わせて、どこまで収束したかが読める
- **エラー表示**: API失敗時に赤いボックスでメッセージ表示。実行は停止する
- **比較モードへのリンク**(Issue #46): 見出し付近に「比較モード」への小さなリンクを置く。`/compare` に遷移する(下記)

### F1'. 比較モード(`/compare`)と URL パラメータ(Issue #46)

同じ問題を Jev と Claude に同時に解かせて見比べるための、通常ページとは別の画面。判定ループの `state` / `queue` / 実行世代はページに1組しかない設計を崩さないため、**Jev/Claude 2 インスタンス化はしない**。代わりに、通常ページ(`GET /`)を `<iframe>` で2枚並べ、`/compare` を返す親ページが `postMessage` で両方を同時に操作する(`docs/DESIGN.md` 4.2・8章)。

**通常ページ(`GET /`)の URL パラメータ。** `location.search` を起動時に1回読む(`readUrlOptions()`)。`localStorage` の設定より優先するが、`localStorage` へは一切書き戻さない(通常ページの設定を汚さない)。

| パラメータ | 意味 |
|---|---|
| `puzzle=<81文字>` | `1`〜`9` と `.` からなる81文字。この盤面で開く。`SOLUTION` はソルバー(`solveCount`)で求め、**一意解のときだけ**採用する(形式不正・非一意なら無視して固定問題のまま) |
| `model=jev\|claude` | モデル切り替えの初期値を上書きする |
| `order=scan\|confidence` | 順番切り替えの初期値を上書きする |
| `speed=slow\|fast` | 速度切り替えの初期値を上書きする |
| `embed=1` | 埋め込みモード(下記)にする |

**埋め込みモード(`embed=1`)。** コントロール群(実行/リセット/新しい問題/各トグル)・Claude 設定パネル・較正図・プロンプト枠・見出し(h1・サブタイトル)を隠し、グリッド・凡例・統計カード・現在の判定・周回ログ・エラーボックス・完了バナーだけを描く。親(比較シェル)からの `message` を、`event.origin` が自分と同一オリジンのときだけ受け付ける:

| `message` の `type` | 効果 |
|---|---|
| `run` | `run()` を呼ぶ |
| `stop` | `stop()` を呼ぶ |
| `reset` | `reset()` を呼ぶ |
| `newPuzzle`(+ `puzzle`) | `puzzle`(81文字)を上記と同じ検証で差し替える |
| `setSpeed`(+ `mode`) | 速度切り替え |
| `setOrderMode`(+ `mode`) | 順番切り替え |

また、`render()` のたびに現況(モデル識別子・周・累計正解数・総マス数・残りマス・実行中か・停止中か・完了か・完了周数・強制終了か・エラー文言)を `{ type: "status", ... }` として `window.parent` へ `postMessage`(第2引数に `location.origin`)する(`embed=1` のときだけ)。

**比較シェル(`GET /compare`)。** 上部バー(新しい問題 / 実行(両方が実行中なら「停止」に切り替わる)/ 停止 / リセット / 速度トグル / 順番トグル / 難易度トグル)と、左右2枚の `<iframe>`(`src="/?embed=1&model=jev&puzzle=…&speed=…&order=…"` / `…&model=claude…`。初期盤面は固定問題)を並べる。各 iframe の上に、モデル名・経過時間(実行開始からの秒。親が計る)・「N周目」・「正解 K / 総マス」・状態(実行中 / 停止中 / 完了(N周) / 強制終了(15周) / エラー: 文言)の見出しを表示し、iframe からの `status` メッセージで更新する。Claude の API キーが未設定(`loadAnthropicKey() === null`)なら右側の見出しに注記を出す(キー入力はここには置かない。通常ページの設定パネルで保存する)。**片方がエラーで止まっても他方は続く。**

### F2. 1マスの判定フロー

**確信度順モード(Issue #38)では、この判定フローの前に「マス選び」が入る(F3)。** 以下は
選ばれたマス(左上からモードでは queue の先頭)に対する数字判定の手順で、どちらのモードでも共通。

1. 対象マスをフォーカス表示し、確率バーを空にする
2. モデルが「Jev」なら `POST /api/judge` にスナップショットと対象座標を送る。「Claude」なら **ブラウザから `https://api.anthropic.com/v1/messages` を直接呼ぶ**(BYOK。4章「Claude 経路」)。どちらも同じスナップショット(対象マスは `.`)を渡し、返ってくる形も同じ `{ probabilities, choice, confidence, request }` に揃える
3. 返ってきた `probabilities` を1〜9の順に並べてバー表示。`choice` の棒を強調
4. `choice` の数字をマスに入れる
5. 正解(`SOLUTION`)と比較し、緑/赤で色付け
6. じっくりモードなら 700ms 待ってから確定、確定後 150ms 待って次へ。最速モードは待ち時間ほぼゼロ

**停止(Issue #32)。** 「停止」を押すと、盤面(判定済みのマス)・周回ログ・統計・実行中の周は保ったまま止まる(リセットとは違い、進行状況を捨てない)。判定中(フォーカス中)のマスがまだ確定していなければ、その結果は破棄して記録にも残さない。**そのマスは「再開」(=実行の続き)でもう一度最初から聞き直す**(F1不変条件と同じく、確定していない推測を Jev に見せたまま次に進めることはしない)。判定中でない(結果待ち・確定直後の待ち時間中だけの)タイミングで止めた場合は、次のマスから続く。

### F3. 周回ロジック

- 1周目の対象は「与えられていないマス」すべて(行優先順)
- 周が終わったら「N周目: M中K正解 (P%)」をログに追記
- **不正解だったマスだけ**を次の周の対象にする。正解したマスは確定し、二度と判定しない
- 次の周の判定では、**前の周までの推測(正誤問わず)を含むスナップショット**を Jev に渡す。つまり周を重ねるほど文脈が増える
- ただし **再判定するマス自身は空(`.`)にして送る**。そのマスの前回の推測を Jev に見せない(アンカリングを避ける)
- 不正解が0になった周で終了。その周の番号を「何周で全部正解したか」として表示
- 安全弁として15周で強制終了
- **周をまたぐ待ち時間中(1周終わって次の周が始まるまでの間)に「停止」した場合は、次の周の先頭から再開する**(Issue #32)。次の周の対象マス・周番号は、この待ち時間に入る前(周が終わった直後)にすでに確定しているため
- **確信度順モード**(Issue #38、順番トグルで選ぶ)では、周の対象マスを左上から順に聞くのではなく、まず「その周でまだ確定していないマス(= その時点の `queue`)のうち、最も確定しやすいマス」を Worker の `ask:"cell"`(4章)/ Claude の同種のスキーマ(4章「Claude 経路」)で選ばせ(**マス選び**)、選ばれたマスを従来どおり `ask:"digit"` で聞く(F2)。**候補は常にその周の残りマス(`queue`)そのもの**で、マス選びに送る盤面は `queue` の全マスを `.` にしたスナップショット(`buildSelectionSnapshot()`。2周目以降は前の周の不正解の推測が残ったままだと Worker が空マスとして数えないため、これらも `.` にする必要がある)。選ばれたマスは `queue` から取り除いてから数字判定(F2)に進むので、1マスあたりの API 呼び出しが2回になる(5章)。周の区切り・集計・15周の安全弁は左上から順のときと同じ
  - マス選び中に「停止」した場合(まだどのマスも選ばれていない)は、選び直しから再開する(`queue` はそのまま。再キューは不要)。選ばれたあとの数字判定中の停止は F2 の従来どおり(`queue` の先頭に戻す)
- **数字ごとモード**(Issue #45)では、マスではなく数字を主語にして「この数字はどの空マスに入るか」を Worker の `ask:"where"`(4章)で一度に聞く。空マスごとの `noul` がまとめて返るので、**1 盤面 × 1 数字につき API 呼び出しは 1 回**(1〜9 を一通り聞くと 1 周あたり最大 9 回。左上からの 51 回、確信度順の約 102 回と比べる数字)。送る盤面はマス選びと同様、**その周でまだ確定していないマスを `.` にしたスナップショット**(`buildSelectionSnapshot()` 相当)にする(前の周の不正解の推測が残ったままだと Worker が空マスとして数えず、質問から漏れる)。**現時点では Worker 側(`ask:"where"`)だけが入っており、フロント(モードの切り替えと表示)は別 PR**

### F4. 速度モード

| モード | 確定前の待ち | 確定後の待ち | 周と周の間 |
|---|---|---|---|
| じっくり確認 | 700ms | 150ms | 250ms |
| 最速 | 0ms | 20ms | 80ms |

いずれもAPIの実レイテンシは別途乗る。「最速」は Jev の速度をそのまま体感するためのモード。

### F4'. 難易度モード(ヒント数)

「新しい問題」で生成する問題の目標ヒント数(与えられた数字の数)は難易度トグルで選ぶ。数字が少ないほど手がかりが減り、Jevにとって難しくなる。

| 難易度 | 目標ヒント数 |
|---|---|
| やさしい | 36 |
| ふつう(既定) | 30 |
| むずかしい | 25 |

「むずかしい」はジェネレーターの都合で目標ちょうどに届かず26〜28個で止まることがある(下限は24。`docs/DESIGN.md` 5章)。

### F5. エラー処理

- `/api/judge` が 2xx 以外、またはJSONでない、または `answers.digit` が無い場合はエラー扱い
- フロントは赤いエラーボックスに理由を表示し、`running=false` にして停止
- 停止後は **実行ボタンを無効化する**。復帰は **リセットのみ**で、盤面・周回ログ・統計をすべて捨てて **1周目の最初からやり直す**(途中から再開はしない。何周目のどのマスから再開すべきかが一意に決まらず、実験としての読み方も濁るため)
- リセットは進行中の判定があっても安全に行える。リセット時点で飛んでいる `/api/judge` の結果や予約済みのタイマーは、新しい盤面には一切反映しない(`docs/DESIGN.md` 4.3 の実行世代)
- **リセット時は進行中の `/api/judge` リクエストを中断する**(`AbortController`。結果を無視するだけでなく、リクエスト自体を打ち切って無駄な待ち時間とレート制限消費を減らす。`docs/DESIGN.md` 4.3、Issue #19)
- Worker 側は 400(入力不正)/415(`content-type` が `application/json` でない)/429(レート制限超過)/502(AI呼び出し失敗・予期しない形式)/503(レート制限のカウンタが記録できない)を返し、`error` フィールドに日本語の理由を入れる

### F6. レート制限

Workers AI の利用コストが青天井にならないよう、`/api/judge` に2段構えの固定ウィンドウ・レート制限をかける。

- **IP単位**: `CF-Connecting-IP` ごとに、**120回 / 3600秒(1時間)**(`wrangler.toml` の値。2026-09-22 にオーナー判断(Issue #20)で 30 から緩和。数独 1 問 ≈ 78 判定を 1 時間で完走できる値。コード側のフォールバックは 30)
- **全体**: 全アクセス合算で、既定 **500回 / 3600秒(1時間)**。IP単位の制限を分散アクセスで回避されても、これが最終防衛ラインになる
- どちらか一方でも超過したら **429** を返す。`error` に日本語の理由、`Retry-After` ヘッダーに残り秒数を入れる
- 上限値・ウィンドウ幅は `wrangler.toml` の `[vars]`(`RATE_LIMIT_PER_IP_MAX` / `RATE_LIMIT_GLOBAL_MAX` / `RATE_LIMIT_WINDOW_SECONDS`)で調整する。**コードを変更せず、値を書き換えて再デプロイするだけで調整できること**
- カウンタの保存先は **Durable Object**(クラス `RateLimitCounter`、バインディング名 `RATE_LIMITER`)。全体用に1インスタンス、IPごとに1インスタンスを使う。Durable Object はインスタンスが1つで直列実行なので、分散アクセスでも数え落としが起きない(当初は Workers KV を使っていたが、結果整合のため全体上限が分散アクセスに効かなかった。`docs/DESIGN.md` 3.2 / GitHub Issue #10)
- `RATE_LIMITER` バインディングが存在しない場合は、レート制限をかけずに通す(フェイルオープン)。ローカルの `wrangler dev` などバインディングを用意していない場合に動作を止めないため
- バインディングはあるのにカウンタの呼び出しが失敗した場合は、逆に **止める**(フェイルクローズ)。503 と `Retry-After: 60` を返す。回数を数えられない状態で Workers AI を呼ぶと上限が無くなるため
- 不正な入力(400)や AI 失敗(502)も回数に数える。415 とカウンタ障害(503)は数えない(レート制限より前で止まる、または数えられないため)

## 4. API 仕様

### `POST /api/judge`

リクエスト:

````json
{
  "puzzle": [
    "53..7....",
    "6..195...",
    ".98....6.",
    "8...6...3",
    "4..8.3..1",
    "7...2...6",
    ".6....28.",
    "...419..5",
    "....8..79"
  ],
  "target": { "row": 0, "col": 2 }
}
````

- `puzzle`: 9要素の文字列配列。各要素は9文字。文字は `1`〜`9` と `.`(未確定)のみ
- `target.row` / `target.col`: 0〜8 の整数
- `ask`(任意): `"digit"`(既定)/ `"cell"` / `"where"`。省略時は従来どおり `"digit"`。`"cell"` は「空マスのうち最も確定しやすいマスはどれか」を、`"where"` は「指定した数字がどの空マスに入るか」を聞くモードで、どちらも `target` を取らない(後述)
- `content-type` ヘッダーのメディアタイプ(`;` の前)が `application/json` であること(`charset` 等のパラメータは付いていてよい)。そうでなければ 415(レート制限より前に弾く。他サイトのページからの呼び出しを塞ぐため。`docs/DESIGN.md` 7章)
- 次のいずれかに当てはまる場合は 400: JSON でない / 上記の形式でない / `target` のマスが `.`(空)でない / `puzzle` の埋まっているマスが 17 個未満 / `ask` が `"digit"` `"cell"` `"where"` 以外
- 盤面はブラウザ側のジェネレーターが作るので、Worker は特定の問題(初期配置)を持たない。どの問題から来たリクエストかは検証せず、「数独の盤面として受け付けられる形か」だけを見る
- 行・列・箱の矛盾は **検証しない**。過去の周の不正解の推測をそのまま残して送る設計なので(F3)、矛盾した盤面が来るのは正常な状態である
- 17 は一意解を持つ数独の最小ヒント数。これ未満の盤面は数独として成立しないので弾く

レスポンス(200):

````json
{
  "probabilities": { "1": 0.03, "2": 0.05, "3": 0.02, "4": 0.61, "5": 0.08, "6": 0.07, "7": 0.04, "8": 0.06, "9": 0.04 },
  "choice": "4",
  "confidence": 0.31,
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "target": { "row": 0, "col": 2 }, "note": "..." },
    "questions": { "digit": { "type": "choice", "instructions": "...", "criteria": { "1": "the digit 1", "...": "..." } } }
  }
}
````

- `probabilities`: キーは `"1"`〜`"9"` の文字列、値は 0〜1(Jev の契約。Worker は有限の数値であることだけを検証し、範囲は検証しない)
- `choice`: Jev が選んだキー(文字列)
- `confidence`: Jev が返す独自の確信度。`probabilities[choice]` とは一致しない(実測: 0.20 に対して 0.10 など)。較正の検証には `probabilities` を使う
- `request`: `env.AI.run` に渡したペイロードそのもの。`state.puzzle` / `state.target` / `state.note` / `questions.digit.{type,instructions,criteria}`(フロントの「モデルに送ったプロンプト」パネルがそのまま表示する。Issue #34)。502 にも付く。400/415/429/503 には付かない(まだ payload を組み立てていないため)

#### `ask: "cell"`(マス選び。Issue #38)

「空マスのうち、どのマスが最も確定しやすいか(その数字を最も自信を持って言えるか)」を Jev の `choice` で聞くモード。確信度順モード(3章 F3)の1ステップ目に使う。

リクエスト:

````json
{
  "puzzle": ["53..7....", "6..195...", "..."],
  "ask": "cell"
}
````

- `puzzle` の形式チェック(9行×9文字、`1`〜`9` と `.`、埋まっているマスが17個以上)は `ask:"digit"` と同じ
- **`target` は取らない**。付いていたら 400(どちらのつもりのリクエストか曖昧にしないため、無視せず弾く)
- 空マス(`.`)が1つも無ければ 400(聞くものが無い)
- Jev に渡す `criteria` は **空マスだけ** を行優先の順に並べたもの。キーは `"r" + row + "c" + col`(例 `"r0c2"`)、値は `"row 0, column 2 (zero-based)"`。Jev の `choice` は選択肢を255個まで取れるので、空マスは最大64個(埋まっているマスが17個以上という共通条件のため)なので1回で聞ける
- `state` は `{ puzzle, note }` のみ(`target` が無いぶん `note` も専用の文面)
- レート制限は `ask` によらず **1呼び出し = 1カウント**。確信度順モードは1マスあたり2回呼ぶので、その分だけ回数を消費する(3章 F6 の上限は据え置き)

レスポンス(200):

````json
{
  "probabilities": { "r0c2": 0.03, "r0c3": 0.01, "...": 0.0 },
  "choice": "r0c2",
  "confidence": 0.18,
  "cell": { "row": 0, "col": 2 },
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "note": "..." },
    "questions": { "cell": { "type": "choice", "instructions": "...", "criteria": { "r0c2": "row 0, column 2 (zero-based)", "...": "..." } } }
  }
}
````

- `probabilities`: キーは criteria のキー(空マスの一覧)と **ちょうど一致**(個数も各キーも)。値は有限の数値
- `choice`: 選ばれた空マスのキー。`cell` はそれを座標に分解したもの(フロントが毎回パースしなくて済むように添える)
- `confidence` / `request`: `ask:"digit"` と同じ意味
- `answers.cell` が無い / `probabilities` のキーが criteria と一致しない(余計なキー・欠け・キー名違い)/ `choice` が criteria のいずれでもない / `confidence` が数値でない、のいずれかなら 502(`raw` と `request` を添える)

#### `ask: "where"`(数字ごと。Issue #45)

「いま聞いている数字(`digit`)が、**どの空マスに入るか**」を空マスごとの `noul`(0〜1 の確率)でまとめて聞くモード。数独を解く人間の「4 はどこ?」という見方に対応する。**1回の `env.AI.run` に空マスの数だけ質問を入れる**(2026-09-22 に 51 個の質問を1回で投げて 51 件返ることを実環境で確認済み。`docs/DESIGN.md` 3.4)。

リクエスト:

````json
{
  "puzzle": ["53..7....", "6..195...", "..."],
  "ask": "where",
  "digit": "4"
}
````

- `puzzle` の形式チェック(9行×9文字、`1`〜`9` と `.`、埋まっているマスが17個以上)は `ask:"digit"` と同じ
- `digit`: `"1"`〜`"9"` の **文字列**。欠けている・数値(`4`)・範囲外(`"0"` / `"10"`)なら 400(`"ask:whereではdigitに1〜9の文字列を指定してください"`)
- **`target` は取らない**。付いていたら 400(`"ask:whereではtargetを指定できません(盤面全体に聞くため)"`)
- 空マス(`.`)が1つも無ければ 400(聞くものが無い)
- 検証の順番は `ask` → `puzzle` が9要素の配列 → `target` 禁止 → `digit` → 各行の形式 → 17個以上 → 空マスあり
- Jev に渡す `questions` は **空マス1つにつき1問**(`type: "noul"`)。キーは `ask:"cell"` と同じ `"r" + row + "c" + col` で、並びは行優先。各問の `instructions` は `WHERE_INSTRUCTIONS_TEMPLATE`(`"Is the digit {digit} the one that belongs in the empty cell at row {row}, column {col} (zero-based)?"`)に座標と数字を埋めたもの
- `state` は `{ puzzle, digit, note }`(`target` は無く、`note` は専用の文面 `WHERE_NOTE`)
- レート制限は `ask` によらず **1呼び出し = 1カウント**。空マス51個ぶんを1回で聞くので、盤面1つあたり1カウントで済む

レスポンス(200):

````json
{
  "probabilities": { "r0c2": 0.24, "r0c3": 0.02, "...": 0.0 },
  "digit": "4",
  "request": {
    "state": { "puzzle": ["53..7....", "..."], "digit": "4", "note": "..." },
    "questions": { "r0c2": { "type": "noul", "instructions": "Is the digit 4 the one that belongs in the empty cell at row 0, column 2 (zero-based)?" } }
  }
}
````

- `probabilities`: キーは質問キー(空マスの一覧)と **ちょうど一致**(個数も各キーも)。値は各マスの `noul` をそのまま通したもの
- **`choice` / `confidence` / `cell` は付かない**。`noul` の回答は確率だけで、選択も確信度も持たないため(`docs/DESIGN.md` 3.4)。どのマスにするかの判断はアプリ側で行う
- `digit`: 聞いた数字をそのまま返す(応答だけ見てどの数字の問い合わせか分かるように)
- `request`: `ask:"digit"` と同じ意味(`env.AI.run` に渡したペイロードそのもの)
- `answers` が取り出せない / AI Gateway の `state` が `"Completed"` でない / `answers` のキーが質問キーと一致しない(余計なキー・欠け・キー名違い)/ いずれかの `noul` が有限の数値でない、のいずれかなら 502(`raw` と `request` を添える)。`type` は見ない

エラー(400 / 415 / 429 / 502 / 503):

````json
{ "error": "puzzle(9行の配列)とtarget({row,col})が必要です" }
````

429の例:

````json
{ "error": "アクセス元(IP)ごとのレート制限(120回/3600秒)を超えました" }
````

429 のレスポンスヘッダーには `Retry-After`(秒)と `X-RateLimit-Scope`(`ip` または `global`)を、503 には `Retry-After: 60` を付ける。`X-RateLimit-Remaining-IP` / `X-RateLimit-Remaining-Global` は **レート制限を通過したレスポンスすべて**(200 のほか 400 や 502 も。いずれも1回として数えているため)に付く。レート制限より手前で止まる 415 と、制限に引っかかった 429 / 503 には付かない。`RATE_LIMITER` バインディングが無いフェイルオープン時も、残数が存在しないので付かない。

200 を返すのは Jev の回答が期待どおりの形だったときだけ。`answers.<ask>`(`digit` / `cell`)が無い、AI Gateway の `state` が `"Completed"` でない、`probabilities` のキーが期待する集合(`digit` なら `"1"`〜`"9"` の9個、`cell` なら criteria のキー)とちょうど一致しない、値が数値でない、`choice` がそのいずれでもない、`confidence` が数値でない、のいずれかなら 502 とし、`raw` に受け取った生レスポンスを添える。`ask:"where"` は `answers` そのもの(質問キーの集合と各 `noul`)を同じ基準で検証する。`answers` は実環境ではラッパーの中(`result.answers`)に入っている(`docs/DESIGN.md` 3.4)。

### `GET /api/status`

レート制限の残り回数を **読むだけ** で返す(7章の拡張5の最小版)。カウンタは `peek` でしか触らないので、この呼び出し自体は回数に数えられず、残数も減らない。

レスポンス(200):

````json
{
  "window_seconds": 3600,
  "resets_in": 1847,
  "global": { "max": 500, "used": 34, "remaining": 466 },
  "ip": { "max": 30, "used": 6, "remaining": 24 }
}
````

- `window_seconds` / `global.max` / `ip.max`: `wrangler.toml` の `[vars]` の値(`/api/judge` と同じ読み方)
- `resets_in`: 現在の固定ウィンドウが終わるまでの秒数(429 の `Retry-After` と同じ式)
- `ip`: 呼び出し元の `CF-Connecting-IP`(無ければ `unknown`)の分
- `remaining` は `max(0, max - used)`
- `Cache-Control: no-store` を付ける(残数は数秒で変わる)。CORS ヘッダーは付けない
- `RATE_LIMITER` バインディングが無い(フェイルオープン中)ときは、数えていないので残数も無い。200 で `{ "rate_limit": "disabled" }` を返す
- カウンタの呼び出しが失敗したときは 503 と `Retry-After: 60`(`/api/judge` のフェイルクローズと同じ扱い): `{ "error": "レート制限の状態を取得できません" }`
- `GET` のみ。`POST /api/status` は 404

### `GET /`

フロントエンド一式(HTML)を `text/html; charset=utf-8` で返す。それ以外のパスは 404。CORS ヘッダーは付けない(他サイトから `/api/judge` を呼ばせない)。

### `GET /compare`(比較モード、Issue #46)

`GET /` と**まったく同じ** `PAGE_HTML`(セキュリティヘッダーも同じ)を返す。差は「比較シェルを描くかどうか」だけで、フロント側が `location.pathname === "/compare"` を見て分岐する(3章 F1'、`docs/DESIGN.md` 3.1・4.2)。`GET` 以外は 404。

### Claude 経路(ブラウザ → `https://api.anthropic.com/v1/messages`、Worker は関与しない)

モデルが「Claude」のときの 1 判定。Worker を経由せず、ブラウザが Anthropic Messages API を直接呼ぶ(7章 拡張3、Issue #37。`docs/DESIGN.md` 3.6)。

- ヘッダー: `content-type: application/json` / `x-api-key: <利用者のキー>` / `anthropic-version: 2023-06-01` / `anthropic-dangerous-direct-browser-access: true`(ブラウザからの直接呼び出しに必要)
- ボディ(= 画面の「モデルに送ったプロンプト」に出るもの。キーは含まれない):

````json
{
  "model": "claude-opus-5",
  "max_tokens": 16000,
  "system": "<Jev と同じ NOTE> Answer with JSON only, matching the given schema: ...",
  "messages": [{ "role": "user", "content": "Which digit from 1 to 9 belongs in the target cell of this Sudoku grid?\n{\"puzzle\":[...9行...],\"target\":{\"row\":0,\"col\":2}}" }],
  "output_config": { "format": { "type": "json_schema", "schema": { "...": "choice(1〜9) / probabilities(1〜9 の 9 キー) / confidence" } } },
  "thinking": { "type": "adaptive" }
}
````

- `thinking`: 思考ありなら `claude-opus-5` / `claude-sonnet-5` は `{ "type": "adaptive" }`(このとき `max_tokens` は 16000。思考トークンも `max_tokens` に含まれるため)、`claude-haiku-4-5` は `{ "type": "enabled", "budget_tokens": 2048 }`(このとき `max_tokens` は 2048 + 1024)。思考なしなら Opus / Sonnet は `{ "type": "disabled" }`、Haiku は `thinking` を送らない(`max_tokens` は 1024)
- 「キーを消す」は実行中・停止中は押せない(次のマスで止まってしまうため)。キー保存の失敗は判定ループを止めず、設定パネル内の注意書きに出す
- 応答: `content` の最初の `text` ブロックが structured outputs の JSON(`{ "choice": "4", "probabilities": { "1": 0.03, ... }, "confidence": 0.7 }`)。検証は `/api/judge` の 200 と同じ基準(9 キー・有限数・`choice` が 1〜9・`confidence` が数値)。`stop_reason` が `refusal` / `max_tokens`、HTTP が非 2xx(401 キー不正、429、529 など)、ネットワーク失敗は F5 のエラー扱い(理由をエラーボックスに出して停止)
- `probabilities` / `confidence` は **Claude の自己申告**であり較正されている保証はない。それを Jev の値と同じ較正図で比べるのがこの拡張の目的
- レート制限(F6)は関与しない(利用者自身のキーと課金)

#### 確信度順モードのマス選び(Issue #38)

確信度順モード(3章 F3)で Claude をモデルに選んでいるときのマス選び1回ぶん。数字判定と同じ経路・同じ思考(thinking)の規則を使うが、`system` / `messages` / スキーマがマス選び用になる。

````json
{
  "model": "claude-opus-5",
  "max_tokens": 16000,
  "system": "<Jev と同じ CELL_NOTE> Answer with JSON only, matching the given schema: ...",
  "messages": [{ "role": "user", "content": "Which empty cell of this Sudoku grid can be filled in with the most certainty?\n{\"puzzle\":[...9行...]}" }],
  "output_config": { "format": { "type": "json_schema", "schema": { "...": "choice(候補キーの enum) / probabilities(候補キー全部が required) / confidence" } } },
  "thinking": { "type": "adaptive" }
}
````

- `system` は Worker の `CELL_NOTE`(`ask:"cell"` の `note` と同じ文字列)+ digit 判定と同じ「JSON で答えよ」の指示文。`messages[0].content` は Worker の `CELL_INSTRUCTIONS` + 改行 + `{ puzzle }`(`target` は無い。盤面は `buildSelectionSnapshot()`)
- スキーマの `choice` は `enum` にその時点の `queue` のマスのキー(`"r" + row + "c" + col`、行優先)を並べたもの、`probabilities` はそのキー全部を `properties` / `required` に持ち `additionalProperties: false`。`confidence` は数値。呼び出しのたびに候補(= `queue`)が変わるので、毎回組み立て直す
- 応答の検証は「`probabilities` のキーが候補キーとちょうど一致・`choice` が候補キーのいずれか・`confidence` が有限数」(digit 判定の検証を候補キー集合に一般化したもの)。`choice`(`"r0c2"` 形式)は正規表現 `/^r(\d)c(\d)$/` で座標に分解する
- `thinking` / `max_tokens` の規則は数字判定と同じ

## 5. 非機能要件

- **1ファイル**: Worker本体・フロントを `src/index.js` 1つに収める。ビルド不要
- **秘密情報を持たない**: APIトークン等はリポジトリに含めない。Workers AI の認証はバインディング経由。Claude 経路の API キーは利用者のブラウザ(`localStorage`)にだけあり、Worker にもリポジトリにも無い(4章「Claude 経路」)
- **コスト**: Jev は入力$0.042/100万トークン・出力無料。**Workers AI のニューロンではなく AI Gateway のクレジットで課金される**(`typesafe/jev` は AI Gateway 経由で提供されている。`docs/DESIGN.md` 3.4)。1問51マス×数周で誤差程度
- **レイテンシ**: Jev 公称 100ms 前後だが、**Worker 経由の実測は 1.0〜1.7 秒**(2026-09-21)。AI Gateway を挟む分の往復が乗る。最速モードで体感できるのはこの実測値のほう
- **認証なし・レート制限あり**: 公開デモとして誰でもアクセス可。ログイン等は無いが、F6のレート制限でコストの上限を確保する
- **CSP と埋め込み**(Issue #46): `GET /` `GET /compare` の `Content-Security-Policy` は `frame-ancestors 'self'`(同一オリジンの iframe にだけ埋め込みを許可)。比較モード(`/compare`、3章 F1')が自分自身を `<iframe>` で2枚埋め込むため、他サイトからの埋め込みは禁止したまま(`'none'` ではなく)`'self'` に緩めた。埋め込み先(`embed=1`)は親からの `message` を `event.origin` が同一オリジンのときだけ受け付ける
- **テスト可能**: `npm test`(Node 標準の `node:test`)で、Cloudflare の認証なしに Worker のロジックを検証できる。CI(GitHub Actions)で自動実行する
- **コスト**(2026-09-21 の実測トークン数にもとづく試算。1ドル=150円換算):
  - 1回の判定(実測 約670入力トークン): 約$0.000028(0.0042円)
  - 数独1問フル実行(51マス×平均3周≈78回): 約$0.0022(0.33円)
  - 全体上限(既定500回/時)に24時間張り付いた場合の理論上の最悪値: 約$0.34/日、月$10程度
  - `ask:"where"`(数字ごと、#45)は 1 回で入力 約1,950 / 出力 約970 トークン(空マス51個の実測。`docs/DESIGN.md` 3.4)と `digit` の約3倍。レート制限は回数でしか数えないので、全体上限に張り付いた最悪値は約 $1/日 になる(それでも小さいので上限は据え置き)
- **確信度順モードは1マスあたりAPI呼び出しが2回**(マス選び+数字。Issue #38、3章 F3)。左上からモードの2倍のコスト・レート制限消費・所要時間になる(F6のIP単位上限120回/時に対して、確信度順で1問(51マス×平均3周)を完走するには単純計算で約156回かかり、1時間では収まらないことがある。急ぐ場合は左上からモードを使う)
